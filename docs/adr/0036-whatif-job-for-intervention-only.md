# ADR-0036: What-if は「介入付きで学習された WM」にだけ、ジョブと読み出しで入れる

- 日付: 2026-11-08
- 状態: 採択（ADR-0035 の M10-03 / M10-04）
- 触る層: worldmodel（スプールの介入列・`action_dim`）、reasoning（ジョブ）、knowledge（シナリオの表）、api（`scenarios`）

## 文脈

`run_scenario` / `encode_intervention` / `promote_scenario` はあるが、運用で呼ぶ者がいない。入口を作る前に、**運用の WM で What-if が意味を持つか**をコードで確かめた:

1. **介入（`INTERVENTION`）**: Koopman は介入付きで学習していなければ `step(action=...)` を拒否する（`_control is None`）。本リポジトリの学習ジョブ（`train_koopman`）は
   スプールの観測だけで fit し、介入列を渡さない。**運用で作られる WM は、いまは必ず介入を拒否する。**
2. **計画差分（`PLAN_DIFF`）**: 条件付けは決定的な特徴ベクトルを潜在の末尾に加算するだけで、効き方は**学習されていない**（`worldmodel/context.py` の docstring。学習は設計書 §4.5 の段階 2）。
   計画差分の What-if は「特徴を足した分だけ動く」数値で、物理効果の予測ではない。出せば、介入の効果が 0 でない嘘になる（`whatif.py` の冒頭が警告している形の裏側）。
3. **反実仮想（`COUNTERFACTUAL`）**: 妥当性スコアに介入の観測件数が要る。`ActionEvent` を永続化していない（H-07）ので件数が数えられず、常に 0（外挿）になる。

## 決定

1. **入れるのは `INTERVENTION` だけ。** `PLAN_DIFF` と `COUNTERFACTUAL` は入口を作らない（理由は上の 2・3。条件付けが学習されたとき、`ActionEvent` を永続化したときに再起票）。
2. **介入付きで学習された WM でだけ実行する。** 実行前に `KoopmanModel.action_dim`（制御項の列数。無ければ `None`）を見て、`None` なら**理由を示して拒否する**（終了コード 2）。拒否しないで介入なしの rollout を返す経路は作らない。
3. **介入付きの学習をスプールから可能にする。** スプールの観測窓に任意の `actions`（時刻と同じ長さの行 × 介入次元）を許し、`train_koopman` が渡す。介入の列は現場のエッジ（本リポジトリ外）が置く。
   `channel` は「その行列の列番号」で、アクション型との対応は呼び出し側が与える（`--action-type` の IRI と `--channel`）。
4. **結果の形。** 起点の最新の潜在から、同じ `seed` で**介入なし（基準）**と**介入あり**の 2 本を rollout し、プローブ通過後のフルーエント確率の差を先行時間ごとに返す。
   `hypothetical` のアサーション（介入あり）は `urn:sbp:scenario:<id>` に書き、主信念には入れない（不変条件 3）。`promote_scenario` の入口は作らない（採用は人の決定で、コマンドの設計が別に要る）。
5. **シナリオの索引表 `scenarios`**（alembic 0017）。識別子は `(拠点, 実体, フルーエント, WM 版, 起点, アクション型, チャンネル, 強さ, 地平)` から決める uuid5（再実行で二重に積まない）。
   読み出しは GraphQL `scenarios`。`hypothetical` は ABAC で既定は見えない（許可に様相 `hypothetical` を入れた要求者だけ）。

## 結果

- 運用で What-if が呼べる。ただし介入付きの学習データが無い間は拒否する——**拒否が運用の既定**であることを、拒否の理由と終了コードで見えるようにする。
- 限界: One-hot 的な符号化（強さ 1 チャンネル）のみ。介入の効果の妥当性（観測件数）は出さない。UI は作らない。

## 未決
