# ADR-0020: 証拠の三源並置は「寄与」を単位に、実体 × フルーエント × 区間で引き、寄与を投影表に残す

- 日付: 2026-11-07
- 状態: 採択
- 触る層: knowledge（寄与の投影）、services（belief-worker）、api（GraphQL 資源）、apps/ui、infra（alembic 0013）

## 文脈

設計書 §8.2・§10.3 は、不一致と信念を人が判断するときに三源（観測・記録・計画）を並べて見せることを求める。
M8-26 で運用の信念更新は三源になった。UI の不一致キューは参照 IRI の一覧までで、「三源の並置はまだ作れて
いない」と画面に出している（所見 84）。所見 84 と TASK は、足りないものを (a) アサーション ID で信念を引く API、
(b) 来歴の `contrib` から源を判定する経路、とした。

着手前に確かめると、**前提が 2 つ誤っていた**（所見 125）:

1. **寄与（`contrib`）はどこにも永続化されていない。** `BeliefUpdate.contribution` はメトリクスにだけ使われ、
   アサーションの来歴は `provenance: str`（バンドル IRI）で、寄与は Oxigraph にも Postgres にも残らない。
   説明サービス（`reasoning/explain.py`）は再計算で寄与を作っていた。「来歴から源を読む」経路は存在しない。
2. **不一致の `assertions` はアサーション ID ではない。** 照合規則は `assertions=(single.fluent,)`（フルーエント型）や
   イベント型を入れる。ID 引きの API を作っても、引く相手がいない。引けるのは **実体 × フルーエント × 区間**。

## 選択肢

### 問い 1: 寄与をどこに残すか

1. **投影表 `belief_contributions`（Postgres、追記専用）。** belief-worker が信念を書くとき、
   `assertion_id` をキーに三源の寄与を書く。アサーション本体は触らない。
2. アサーションの来歴バンドルを PROV グラフ（Oxigraph）に展開して寄与を持つ。設計書 §6.4 の方向だが、
   文ごとにトリプルが数個増え、バンドル化（証拠集合は参照で持つ）の設計も要る。並置の読み出しは
   時系列の範囲取得なので、SPARQL より表が素直。将来の展開の余地は残す。
3. 読み出しのたびに再計算する（説明サービスの形）。再計算は入力（当時の記録・観測）を全部引き直す必要があり、
   記録の主張は永続化されていない。当時の値を再現できない。

### 問い 2: 並置の単位と鍵

1. **単位は寄与、鍵は（実体, フルーエント, 区間）。** 不一致の `subjects` × `assertions` のフルーエント × `interval` から、
   区間に有効だった `inferred` の信念の時系列と各点の寄与を並べる。計画は `planned` の文をそのまま並べる。
2. 様相で 3 列に分ける。成立しない（三源は様相では分かれない。所見 84: 業務記録由来も推定を経て `inferred`）。
3. アサーション ID 引き。引く相手がいない。

### 問い 3: 書く順序

**寄与 → アサーション。** 逆だと、アサーションがあるのに源が分からない文が残りうる。寄与だけ残る孤児は無害
（読み出しはアサーションの有無ではなく寄与の時系列を見るので、孤児が点として出ないよう、読み出しは
`AssertionStore` の信念と突き合わせる）。

## 決定

問い 1: 投影表。問い 2: 寄与を単位に、実体 × フルーエント × 区間。問い 3: 寄与 → アサーション。

- 表 `belief_contributions`: `assertion_id`（主キー）/ 拠点 / 実体 / フルーエント IRI / 時刻 / 事前 / 事後 /
  観測寄与 / 記録寄与 / 計画寄与 / 起因イベント ID / 除外した記録数。
- API は GraphQL の新しい資源 `beliefEvidence(entity, fluent, from, to)`。信念の点（確率・寄与・支配的な源・起因
  イベント）と区間の計画を返す。ABAC は既存の信念と同じ経路。
- UI は不一致の行から開く 3 列（観測 / 記録 / 計画）+ 事後。**どちらが正しいかは示さない。** 寄与が 0 の源は
  「寄与なし」と明示し（空欄で「証拠が無い」と誤読させない。所見 32）、寄与が記録されていない過去の信念は
  「寄与は記録されていない」と出す。結合（`_couple`）が書く信念は寄与を持たず、「結合」として別に表示する。

## 帰結

- **不変条件 1・2**: アサーション本体を変えない。寄与は追記専用の投影で、真実のフラグではない（読み出し専用の説明）。
- **不変条件 6**: 除外した記録数を残す（監査隔離が働いたことを後から確認できる）。
- **不変条件 7**: 寄与は対数尤度比の絶対値（生の大きさ）で、`belief` ではない。UI は正規化して見せる。
- **構成**: alembic が 12 → 13。ワーカー数は 6 のまま。belief-worker が Postgres に書く（既に冪等ストアと指標で接続している）。
- **テスト**: 単体（書き込みの順序・結合の信念は書かない・配線なしの報告、UI の純粋関数）、統合（belief-worker →
  表 → API が三源の寄与を返す）。

## 未決

- **信念ビュー（実体ごとの三源 + 事後の時間軸、as-of スライダ）への展開。** API は流用できる。
- **過去の信念への寄与の遡及。** この変更より前の信念は寄与を持たない（「記録されていない」と出す）。
- **記録の主張そのものの永続化。** 取込の `business_records` は存在だけ。主張の確率は寄与（記録寄与）として残るが、
  個々の主張は残らない。
- **PROV グラフへの展開**（問い 1-2）。バンドル単位の来歴（設計書 §6.4）を実装するときに統合する。
