# ADR-0033: `/stream/{topic}` を消す（H-03）。UI は localhost 限定のまま運用に出さない（H-02）

- 日付: 2026-11-08
- 状態: 採択
- 触る層: api

## 文脈

- H-03: M8-18 / M8-19 で UI の 4 ビューすべてが GraphQL の資源を読むようになり、`/stream/{topic}` の購読者は 1 人も居ない。`build_app` は `stream_reader=None` を渡すので常に 503 を返していた。
- H-02: UI の認証方式（OIDC・プロキシ）。人の回答（2026-11-08）: **UI を外部公開する予定はない。外部クライアントが `/stream` を購読する予定もない。**

## 決定

1. **`/stream/{topic}` を消す**（`create_app` の `stream_reader` 引数、エンドポイント、関連テスト）。使われない 503 のエンドポイントは「動くはず」と読まれる。
   必要になったら、購読の方式（SSE / WebSocket）と認可を決めて作り直す（イベントログは残るので失うものは無い）。設計書 §10.1 の表の「ストリーム購読」行は、本 ADR まで未実装・撤回として扱う。
2. **UI の認証方式は決めない（H-02 の (c)）。** UI と API は localhost 限定で運用する。前提条件: 外部へ公開する前に認証方式（OIDC + PKCE を第一候補）を ADR で決める。
   `SBP_ENV=dev` 以外では resolver を渡さず全拒否なので、誤って公開しても漏れない作りは維持する（ADR-0029）。H-25 の偽装（開発用ヘッダ）は、この前提の下でだけ許容する。

## 結果

- API の面は GraphQL・SPARQL（読み取り）・コマンドの 3 形態になる。ストリーム購読を要求する外部クライアントを持つ計画ができたら再起票する。
- ADR-0008 の「購読の UI への反映」の未決は消える（UI はポーリングで足りる）。
