# ADR-0024: プローブ束は「学習ジョブ」が弱ラベルから作り、ゲートを通ったものだけ置き場に置く

- 日付: 2026-11-08
- 状態: 採択
- 触る層: bridge（学習ライブラリ）、scripts（`train_probe`）、core（設定）

## 文脈

bridge-worker は置き場のプローブ束を読む（ADR-0009）。束を**置く運用コードが無い**（所見 100）ので、新規環境では
構築で落ちる。学習・評価・昇格・直列化の部品（`fit_with_bags` / `promote` / `bundle_probe`）はあるが、つなぐ者がいない。
弱ラベルの出所は、業務記録の主張イベント（`BusinessEvent/<フルーエント>`、ADR-0016）と人の回答（ADR-0018）。
潜在は M8-24 のエンコードジョブが索引に書く。

## 決定

1. **学習ライブラリは `sbp.bridge.training`（純粋）、運用の入口は `scripts/train_probe.py`。** 層の向き
   （integration は bridge を import できない）のため、主張イベント → `TimeBag` の変換も bridge に置く。
2. **弱ラベル**: 主張イベントの確率 p（信頼性モデルを通した値）から。p > 0.5 は正例バッグ、p < 0.5 は負例バッグ、
   p = 0.5 は情報が無いので使わない。重みは `|2p − 1|`（(0, 1]）。区間は有効時間の始端 ± max(不確実幅, 下限)。
   下限は設定 `weak_label_min_half_width_s`（点時刻のバッグを作らない）。
3. **時間順の三分割**: 潜在の時間軸を 訓練 / 較正 / 評価に前から切る（既定 0.6 / 0.2 / 0.2）。**ランダム分割にしない**
   ——時系列の近傍が漏れて評価が甘くなる。バッグは区間の終端が属する枠に割り当てる。
4. **評価ラベルは弱ラベル由来**（バッグに入る標本のみ。正バッグ内 = 真、負バッグ内 = 偽）。真値（オラクル）は
   読まない（不変条件 10）。正バッグ内の全標本を真とみなすので AUROC は保守的に出る。これは限界として
   `ProbeMetrics.n_samples` とログに残し、ゲートは緩めない。
5. **ゲートを通らないものは置かない。** `promote()` が例外なら束を作らず終了コード非ゼロ、`probe_auroc` / `probe_ece`
   だけ記録する（落ちた理由が見えるように）。通ったら `ArtifactStore.put`（上書きしない）。
6. **整合残差**は評価枠の記号化（閾値 0.5）に対する `alignment_residual` の値。ちらつきを数える。
   比較対象の既存 active が無ければ中央値条件は適用されない（`promote` の既存仕様）。
7. 入力: 主張イベントは Kafka を**新しい consumer group で最初から**読み切る（運用の消費者に影響しない）。
   潜在は `LatentIndex.since`。

## 結果

- bridge-worker を起動できる経路が運用手順になる。データが足りない（各枠に両クラスの標本が `probe_min_labelled` 未満）
  ときは束を置かず、理由を出す。
- 限界: 弱ラベルの粗さ（4）。実データでの閾値の妥当性は H-01 系の実機検証後。

## 未決

- 複数フルーエントを 1 回で学習する束ね方（いまは 1 フルーエント 1 実行）。
- 昇格後の入れ替え（既存 active の deprecated 化）の運用は version-promotion runbook に従う。
