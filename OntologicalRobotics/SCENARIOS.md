## 1. 目的と位置づけ

T1〜T7 は OR の**機構**（同一性解決・能力契約・信念管理など）を個別に検証する合成タスクである。本書の T8〜T14 は、それらの機構が**実業務の成否を握る状況**を再現し、ORの価値を業務文脈で実証する。各シナリオは PROJECT.md の仮説 H1〜H7 への対応を持ち、機構検証（T1〜T7）と業務検証（T8〜T14）の二層構造で論証を完成させる。

## 2. シナリオ設計の三原則

### 2.1 オントロジー必要性の試金石
全シナリオは以下の少なくとも一つ（理想は複数）が業務の成否そのものを握ることを要件とする。

- **①越境同一性**: 同一実体が複数システムに別の姿で現れ、束ねないと業務が成立しない。
- **②関係伝播**: 関係を辿る推論（接触の推移閉包、包含、由来）で初めて導ける帰結が意思決定を左右する。
- **③規範と監査**: 「してよいか」「なぜそうしたか」を規則と来歴に照らして機械的に説明する要求がある。

### 2.2 失敗予言（実行可能な帰無仮説）
各シナリオは「**オントロジー無し（B0/B1）ではどう失敗するか**」の予言を仕様として持つ。予言は実装時に**反証テスト（falsification test）**として実行可能化する: 指定クエリ/タスクにおいて B0/B1 が構造的に失敗し、OR-full が成功することをアサートするテストである。予言が書けないシナリオは採用しない。

### 2.3 真値採点可能性
全シナリオの成否・中間状態（汚染集合、custody連鎖、所有関係など）は、シム真値＋業務DB真値から**機械的に導出可能**でなければならない（oracle拡張で実装）。LLM-as-judge には依存しない。

## 3. シナリオ共通仕様

### 3.1 記述テンプレート
各シナリオは以下の項目で定義される（§4 で全件記述）。

`ID / 名称 / 試金石 / 中核仮説 / Tier / 業務文脈 / 世界拡張 / 語彙拡張 / 業務データ拡張 / タスク定義 / 失敗予言 / 真値導出 / 指標 / 劣化ノブ / 受入基準`

### 3.2 共通インフラ拡張（シナリオ群が要求する横断機能）
| ID | 拡張 | 内容 | 必要シナリオ |
|----|------|------|-------------|
| X1 | 割込み指示イベント | 実行中の計画に対する業務指示の割込みと再計画トリガ | S1, S3 |
| X2 | 接触イベント蒸留 | シム接触判定 → `orx-st:ContactEvent`（時刻・両当事者・来歴付き） | S2, S5 |
| X3 | 状態リセットイベント | 洗浄・施錠・認証などの状態遷移イベント語彙 | S2, S5 |
| X4 | ID無し個体の同一性解決 | 記号識別子に頼らない（時空間×視覚署名のみの）アンカリング経路 | S4, S6, S7 |
| X5 | 人間アクタ | 規範・優先制御・引き渡しの相手としての簡易人間エージェント | S5, S7 |
| X6 | 非対称コスト採点 | 誤分類コスト行列と確信度閾値による人間委譲（escalation） | S6 |

X1〜X4 は Tier A で実装。X5/X6 は該当シナリオ着手時。

## 4. シナリオ仕様

### S1 — ロット回収下の倉庫オペレーション（T8）
- **試金石**: ①越境同一性（主）、③監査（従） / **中核仮説**: H2, H6, H7 / **Tier**: A
- **業務文脈**: 平常ピッキング運転中に「ロット L-X に異物混入疑い、即時隔離」の割込み指示。対象個体は棚・把持中・AGV搬送中・出荷待機に散在。
- **世界拡張**: 既存ミニ倉庫に箱のロット属性（テクスチャIDに符号化）、隔離ゾーン、割込みイベント（X1）。
- **語彙拡張**: `orx-biz:Lot`, `orx-biz:memberOfLot`, `orx-biz:RecallOrder`, `orx-st:QuarantineZone`。
- **業務データ拡張**: WMSに lot テーブル（lot↔SKU↔個装ID）、回収指示テーブル。
- **タスク定義（T8）**: (a) 回収対象個体の全件列挙クエリ（位置・状態込み）、(b) 進行中タスクとの衝突判定と再計画、(c) 隔離搬送の完遂、(d) 事後監査クエリ「回収対象が辿った位置履歴」。
- **失敗予言**: B0 は「把持中/搬送中の箱のロット帰属」に答えられない（最新観測ダンプにロット↔個装の参照連鎖が存在しない）。B1 はロボットAの観測個体とWMSレコードの対応付けに失敗する。
- **真値導出**: シム真値の個装ID×WMS lot テーブルの結合で回収対象集合・位置を機械導出。
- **指標**: 列挙の precision/recall、隔離完遂率、隔離完了までの時間、誤隔離数、トークン効率（H7）。
- **劣化ノブ**: ID読取失敗率（ロット帰属が確率化する）、割込みタイミング。
- **受入基準**: ノイズ0で列挙F1=1.0かつ完遂率100%。反証テストが green（B0/B1が指定クエリで失敗）。

### S2 — 食品工場のアレルゲン交差汚染管理（T9）
- **試金石**: ②関係伝播（主）、時間付き状態推論 / **中核仮説**: H5、事象オントロジー全般 / **Tier**: A
- **業務文脈**: ピーナッツ含有品に接触したグリッパ/トレイは、洗浄イベントまでアレルゲンフリー品への接触禁止。汚染は接触イベントの**推移閉包**として伝播する。
- **世界拡張**: 物体への物質タグ、トレイ（中間媒体）、洗浄ステーション、接触イベント蒸留（X2）、洗浄イベント（X3）。
- **語彙拡張**: `orx-st:ContactEvent`, `orx-cap:CleaningEvent`, `orx-biz:AllergenClass`, 派生述語 `orx-st:possiblyContaminatedBy`（時刻依存・導出専用）。
- **タスク定義（T9）**: (a) 任意時刻の汚染可能性集合クエリ、(b) 「この把持は許可されるか」の実行前判定、(c) 混在生産計画の遂行（汚染ゼロ制約下での最短段取り）、(d) 違反ゼロでの完遂。
- **失敗予言**: B0/B1 は接触履歴の推移閉包を計算できず、(b) で偽陰性（汚染グリッパの使用許可）を出す。OR−belief（来歴・時刻無し）は洗浄によるリセットを正しく反映できない。
- **真値導出**: oracle がシム接触ログから真の汚染推移閉包を毎ティック計算。世界グラフ側の導出集合とトリプル単位で照合（**忠実度評価が推論の正しさを直接採点**）。
- **指標**: 汚染集合の precision/recall（偽陰性を重く）、違反件数、生産スループット（過剰保守による損失の検出）。
- **劣化ノブ**: 接触イベント見落とし率（→H5の主検証）、洗浄イベントの観測遅延。
- **受入基準**: ノイズ0で汚染集合F1=1.0・違反0。見落とし率掃引で OR-full と OR−belief の頑健性曲線が分離。

### S3 — 多ベンダー製造ラインの段取り替えと故障時再割当（T10）
- **試金石**: 能力統合（①の機体版） / **中核仮説**: H1, H3 / **Tier**: B
- **業務文脈**: 異ベンダー3機体のライン。品種切替指示（重量・把持面要件が変化）、稼働中の1機が故障。作業指示書（SOP）の工程要求と能力契約の突合せで再割当。
- **世界拡張**: 品種パラメータ化されたワーク、故障注入の「経年劣化モード」（成功率の漸減）。
- **語彙・データ拡張**: SOPに工程要求（重量帯・素材・精度）を構造化記述。`orx-cap:ProcessRequirement` と能力契約のマッチング述語。
- **タスク定義（T10）**: (a) 段取り替え時の全工程再割当、(b) 故障検知後の縮退運転計画、(c) ベンダーD（合成スキーマ）参入のオンボーディング（T5の業務文脈版）。
- **失敗予言**: B1 はベンダー間で語彙が揃わず工程要求×能力の突合せに失敗（誤割当→タスク失敗）。能力統計無し条件は劣化機体への割当を続ける。
- **指標**: 割当正答率、縮退時スループット、統合所要時間・修正行数（H1）、Brierスコア。
- **受入基準**: T3/T5/T6 の合成タスクと整合した結果が業務文脈でも再現されること。

### S4 — プラント点検：図面個体と知覚個体の同一化（T11)
- **試金石**: ①越境同一性（ID無し）＋信念調停 / **中核仮説**: H2, H5 / **Tier**: B
- **業務文脈**: 資産台帳・P&ID上の「バルブV-205」と、ドローン（上方）・地上ロボット（近接）が観測する錆びた金属塊の同一化。異常主張の矛盾（片方は正常、片方は滲み検知）を来歴・確信度で調停し、作業指示を起票。
- **世界拡張**: プリミティブ形状の設備群（バルブ・配管・計器、外観バリエーション付き）、2種視点ロボット、異常の視覚表現（テクスチャ変化）。X4必須。
- **データ拡張**: 資産台帳（位置のラフ座標・系統トポロジ）、点検手順SOP。
- **タスク定義（T11）**: (a) 台帳個体↔知覚個体の対応付け（ID無し）、(b) 矛盾観測の調停と再観測計画、(c) 異常→該当系統SOP→作業指示起票の連鎖。
- **失敗予言**: B0/B1 は台帳と観測の対応を作れず「V-205の状態は」に答えられない。OR-sym は外観バリエーションでの対応付けに失敗（ベクトル署名が無い）。
- **指標**: 対応付け精度、調停の正答率（真値異常との一致）、再観測の効率。
- **受入基準**: 台帳対応付けが位置ノイズ掃引下で OR-full > アブレーション。

### S5 — 病院内搬送：規範が支配する物理空間（T12）
- **試金石**: ③規範と監査（主） / **中核仮説**: 規範層（新規）、H5 / **Tier**: C（P5以降）
- **業務文脈**: 薬剤・検体・リネンの搬送。規制薬物は施錠区画間のみ・custody連鎖の完全記録、検体は取り違え厳禁、人間優先の通行規範。
- **新設**: `ontology/domains/normative.ttl`（義務・禁止・許可、適用条件＝物分類×区画×時間帯×機体認証状態）。計画時の規範チェックAPI。X2, X3, X5。
- **タスク定義（T12）**: (a) 規範適合経路の計画（違反計画の事前棄却）、(b) custody連鎖の完全記録と監査クエリ「先週の規制薬物搬送の全連鎖」、(c) 人間接近時の優先譲歩。
- **失敗予言**: 規範層無し条件は最短経路を選び施錠区画外を通過する（違反）。来歴無し条件は監査クエリに完全回答できない。
- **指標**: 規範違反件数（事前棄却率）、監査クエリ完全回答率、搬送効率の規範コスト。
- **受入基準**: 違反ゼロ＋監査完全回答＋効率劣化の定量化。**監査可能性**という独自評価軸の確立。

### S6 — リサイクル選別：法規制と知覚の橋渡し（T13）
- **試金石**: 双対表現が成否を握る / **中核仮説**: H4 / **Tier**: A
- **業務文脈**: ID無し廃棄物の流入。リチウムイオン電池内蔵品→発火リスクレーン、フロン含有機器→法定処理経路。誤分類コストは非対称（電池見逃し＝火災）。
- **世界拡張**: 外観クラスの異なる物体カタログ（電池内蔵らしさ・機器らしさを視覚特徴に符号化）、選別レーン、人間委譲シュート（X6）。X4必須。
- **語彙・データ拡張**: 規制オントロジー（製品クラス→処理経路の規則）、コスト行列コンフィグ。
- **タスク定義（T13）**: (a) 流入物体の視覚接地（候補クラス＋確信度）、(b) 規制推論による経路決定、(c) 確信度閾値での人間委譲、(d) コスト加重スコアでの選別完遂。
- **失敗予言**: OR-sym はID無し物体で接地不能（全件委譲＝スループット崩壊）。OR-vec は規制推論ができず誤レーン（高コスト誤り）。OR-full のみ両立。
- **真値導出**: 物体カタログの真クラス×規制規則で正解経路を機械導出。
- **指標**: コスト加重誤分類スコア、見逃し率（高コスト誤り）、委譲率とスループット、確信度較正（Brier・キャリブレーション曲線）。
- **受入基準**: コスト加重スコアで OR-full が両アブレーションを有意に上回る。較正曲線の報告。

### S7 — 介護施設：「所有」という知覚不可能な関係（T14）
- **試金石**: ①（情報的関係の同一性） / **中核仮説**: H2, H4, H6 / **Tier**: B
- **業務文脈**: 「佐藤さんの眼鏡を居室へ」。所有は観測不可能な情報的関係であり、入居者台帳・持ち物記録と物理個体の結合が必須。類似物体が複数存在。
- **世界拡張**: 類似外観の小物群（視覚署名の距離を制御パラメータ化）、居室、最終目撃位置の履歴。X4, X5。
- **データ拡張**: 入居者・持ち物台帳（所有関係、特徴メモ）。
- **タスク定義（T14）**: (a) 所有×最終目撃×視覚署名の三系統統合による対象特定、(b) 確信度不足時の確認行動（近接再観測・人間への確認）、(c) 誤配送ゼロでの配送完遂。
- **失敗予言**: B0/B1 は「誰のものか」に答える情報経路を持たない。OR-vec は所有関係を扱えず類似品で誤配送。
- **指標**: 対象特定精度（類似度パラメータ掃引）、誤配送率、確認行動の効率。
- **受入基準**: 類似度掃引で OR-full の優位領域を曲線で特定。

## 5. 実装順序とフェーズ対応

| 順 | シナリオ | スイート | 前提 | 理由 |
|----|---------|---------|------|------|
| 1 | S1 ロット回収 | T8 | P2完了, X1 | 既存世界の最小拡張で最高純度の①検証 |
| 2 | S2 アレルゲン | T9 | X2, X3 | ②関係伝播のOR独自価値を真値採点付きで実証 |
| 3 | S6 リサイクル | T13 | X4, X6 | H4の優位を最も鮮明に分離するアブレーション設計 |

Tier A（S1, S2, S6）完了をマイルストーン **M-Scenario-A** とし、3シナリオ×全条件の比較レポートを成果物とする。

## 6. 横断的な評価・報告要件

- 全シナリオの実験は PROJECT.md §7 の方法論（真理グラフ差分・反実仮想リプレイ・劣化掃引・メタモルフィック）に従う。シナリオ固有の真値導出器は oracle の拡張として実装し、ORコア非依存（CLAUDE.md §3-4）を厳守。
- 反証テスト（§2.2）は `tests/scenarios/` の必須テスト種別とし、CIで常時実行（B0/B1はstubモードで実行可能に設計する）。
- シナリオレポートには必ず「失敗予言の検証結果」「頑健性曲線」「トークン効率」を含める（`orx report` の共通テンプレートに組込み）。
- 語彙拡張は全件 CQ 追加とセットで行う（CQ無き語彙はリグレッション対象外となり腐るため）。

## 7. 用語追補

- **反証テスト**: ベースライン条件が指定タスクで構造的に失敗することをアサートするテスト。シナリオの「オントロジー必要性」の実行可能な証明。
- **推移閉包汚染**: 接触イベント列の推移閉包として定義される汚染可能性集合（S2）。
- **custody連鎖**: 保管・受け渡しの完全な来歴記録（S5）。
- **コスト加重採点**: 誤分類の業務コスト非対称性を反映した評価（S6, X6）。
