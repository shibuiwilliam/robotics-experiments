# PROJECT.md — Ontological Robotics 検証プロジェクト（ORX）

> 本ドキュメントはプロジェクト全体の**定義**である。開発時の作業規約・コーディング指示は別ドキュメント `CLAUDE.md` に分離する。本書は「何を・なぜ・どの基準で」を定め、`CLAUDE.md` は「どう作業するか」を定める。両者が矛盾した場合、本書が優先する。

- プロジェクト名: **ORX** (Ontological Robotics eXperiments)
- 種別: 研究検証用ソフトウェア（シミュレーションベース）
- 実行環境: MacBook (Apple Silicon) 単機・ローカル完結（LLM/テキスト埋め込みのみ OpenAI API）
- ステータス: Phase 0（基盤構築）
- 本書バージョン: 1.0

## 1. ミッションと一行定義

**異種スキーマを持つ複数ロボット・AIエージェント・業務システムの知識を単一オントロジー基盤で結合する「Ontological Robotics (OR)」の有効性を、MuJoCoシミュレーション上で反証可能な形で検証する。**

ORの中核主張は「スキーマ変換（シンタックス統合）ではなく、存在論的コミットメントの統一（セマンティクス統合）が異種システム連携の本質課題であり、共通オントロジー＋アンカリング層がそれを解決する」である。本プロジェクトはこの主張を仮説群に分解し、統制された実験で各仮説を個別に検証する。

## 2. 背景：ORアーキテクチャの要約

本プロジェクトが検証対象とするORアーキテクチャは以下の階層からなる（詳細設計は `docs/design/` 配下に展開する）。

1. **上位オントロジー**: 持続体/生起体、物理的実体/情報的実体などの存在論的コミットメントを全層に強制する基礎層。
2. **ドメインオントロジー（4領域）**: 能力・行為 / 時空間・事象 / 主体・来歴 / 業務・文書。
3. **アンカリング層**: (a) 個体化と同一性解決（複数ロボットの観測と業務レコードを単一IRIに束ねる）、(b) 双対表現（各個体に記号属性と埋め込みベクトルを併置）、(c) 蒸留規律（生データは外部ストアに留め、意味だけをグラフへ流す）。
4. **共有世界グラフ（ABox）**: 全主張に来歴・確信度・時刻を付与した動的世界状態。信念調停を行う。
5. **能力契約**: 各ロボットがアフォーダンス・前提条件・成功率統計を宣言する「身体化されたAPIスキーマ」。エージェント計画とVLA実行の境界契約。
6. **アイデンティティ・スレッド**: 受注→出荷指示→バーコード→物理個体という識別子連鎖による業務‐物理ブリッジ。

## 3. 研究仮説（本プロジェクトの背骨）

すべての実装・実験は以下のいずれかの仮説に紐づかなければならない。仮説に紐づかない機能は作らない。

| ID | 仮説 | 検証タスク | 主要指標 |
|----|------|-----------|---------|
| **H1** | ハブ&スポーク写像は新規ロボット統合コストを下げる | T5 | マッピング自動生成精度、人手修正行数、統合所要時間 |
| **H2** | 同一性解決は複数ロボット協調の成功率とクエリ正答率を上げる | T1 | 同一性F1、タスク成功率 |
| **H3** | 能力オントロジーは計画品質（ロボット選定）を上げる | T3, T6 | 割当正答率、再計画回数、Brierスコア |

## 4. スコープ

### 4.1 スコープ内
- MuJoCoによるミニ倉庫世界（2種以上の異種ロボット、10〜30個体、ID付き/ID無し混在）。
- **意図的スキーマ異質性**: ロボット毎に異なるメッセージ形式（命名規則・構造・単位系）。スキーマ・ファジングによる合成ベンダースキーマの量産。
- **擬似VLAスキルサーバ**: 言語指示インターフェース＋パラメータ化スクリプトスキル＋条件付き故障注入器。
- 模擬業務システム（SQLite WMS: 受注/SKU/出荷指示）と SOP文書コーパス（Markdown）。
- ORコア: 蒸留・アンカリング、知識基盤（RDF＋ベクトル索引）、SHACL検証、エージェント実行系（OpenAIツール使用）。
- **評価装置**: 真理グラフ生成器・忠実度メトリクス、反実仮想リプレイ、劣化ノブ、メタモルフィック・テスト。
- 実験ランナー、統計解析、レポート自動生成。

### 4.2 スコープ外（non-goals）
- 実機ロボット、sim-to-real転移の実証。
- VLA/ポリシーの学習・訓練（実VLA差し替えは Phase 5 のオプション検証のみ）。
- ROS 2 等の重量ミドルウェア導入。
- フォトリアル描画、複数マシン分散、リアルタイム保証。
- 汎用オントロジーの網羅的整備（本プロジェクトの語彙は「実験世界を語るのに十分な最小集合」に限定）。

## 5. システム構成（コンポーネント定義）

| ID | コンポーネント | 責務 | 主要技術 |
|----|--------------|------|---------|
| C1 | `sim` | MuJoCo世界・異種ロボット・センサ・真値状態の公開 | mujoco (Python bindings) |
| C2 | `skills` | 擬似VLAスキルサーバ（pick/place/navigate等）、故障注入 | Python, asyncio |
| C3 | `business` | 模擬WMS（SQLite）、SOPコーパス、識別子スレッドの種データ | sqlite3 |
| C4 | `perception` | レンダリング取得、検出、ローカルCLIP埋め込み、知覚イベント化 | open_clip (MPS) |
| C5 | `anchoring` | 個体化・同一性解決（時空間整合×知覚署名×記号識別子）、確率的マージ/分裂 | Python |
| C6 | `kg` | 世界グラフ（来歴・確信度・時刻付きABox）、TBoxロード、SHACL検証、ベクトル索引 | pyoxigraph, pySHACL, LanceDB |
| C7 | `agent` | OpenAIエージェント実行系。ツール: SPARQLクエリ / 業務DB / スキル呼出 / 文書検索 | OpenAI API |
| C8 | `oracle` | 真理グラフ生成器、忠実度メトリクス（§7.1） | Python |
| C9 | `replay` | 全ストリーム・全LLM応答の記録と反実仮想リプレイ | Python, ディスクキャッシュ |
| C10 | `exp` | 実験ランナー（条件×シード×タスクの直積実行）、統計、レポート生成 | Python |

### 5.1 データフロー（正常系）
```
C1 sim ──観測ストリーム(異種スキーマ)──▶ C4 perception ──知覚イベント──▶ C5 anchoring
C5 ──観測主張(来歴・確信度付き)──▶ C6 kg(世界グラフ)
C3 business ──仮想グラフ写像──▶ C6 kg
C7 agent ◀──SPARQL/検索ツール──▶ C6 kg
C7 agent ──言語指示──▶ C2 skills ──実行──▶ C1 sim
C2 ──実行結果エピソード──▶ C6 kg(能力台帳更新)
C1 ──真値状態──▶ C8 oracle ──忠実度──▶ C10 exp
全ストリーム ──▶ C9 replay(記録)
```

### 5.2 設計上の不変条件（invariants）
1. **生データはグラフに入れない**。点群・画像は `data/runs/` に保存し、グラフには参照IRIと蒸留結果のみ。
2. **世界グラフへの全書込は来歴・確信度・時刻を必須とする**（SHACLで強制）。
3. **同一性は改訂可能な信念**。`owl:sameAs` 直書きせず `orx:anchoredTo`（確信度付き）で表現し、分裂・統合をやり直せる構造とする。
4. **制御とオントロジーのレイテンシ分離**。物理ステップ（高頻度）と知覚・推論（低頻度、例 2Hz）を非同期分離。グラフ推論をシムループに同期させない。
5. **エージェントが世界状態を知る唯一の窓は C6 のツール経由**（ベースライン条件 B0/B1 を除く）。シム真値への直接アクセスは C8 oracle のみに許す。
6. **全実験は記録され、リプレイで再現可能でなければならない**。

## 6. オントロジー定義方針

- 名前空間: `https://orx.local/onto/` 配下。`orx-upper:` / `orx-cap:`（能力・行為）/ `orx-st:`（時空間・事象）/ `orx-prov:`（主体・来歴、PROV-O拡張）/ `orx-biz:`（業務・文書）。個体は `https://orx.local/id/{type}/{uuid}`。
- 既存標準（BFO/DOLCE系の区別、SOMA、OWL-Time、PROV-O）は**採用・剪定・拡張**方針。インポートはせず、必要概念のみ自前TTLに写経し出典をコメント明記（実験の自己完結性とロード速度を優先）。
- OWLプロファイルは EL/QL 相当の軽量範囲に限定。重い推論器は使わず、推論はSPARQLクエリ＋アプリケーションロジックで代替。
- 制約・データ品質は SHACL shapes（`ontology/shapes/`）で表現し、CIで全書込パスを検証。
- **コンピテンシー質問（CQ）はオントロジーの仕様**である。`tasks/competency_questions/` に自然言語＋期待SPARQL＋真値導出規則のトリプルで管理し、回帰テストとして実行する。CQに答えられない語彙変更はリグレッションとみなす。
- 能力契約スキーマ（最低限）: スキル種別、対象アフォーダンス（重量範囲・形状クラス・素材タグ）、作業領域、前提条件/効果、成功率統計（試行数・成功数・直近窓）。

## 7. 評価方法論（本プロジェクトの独自貢献）

### 7.1 真理グラフ差分評価（オントロジー忠実度）
C8 がシム内部状態から毎評価ティックに**完全な真値ABox**を生成し、世界グラフと突き合わせる。
- 指標: トリプルprecision/recall/F1（対象述語集合を固定）、同一性解決F1（真値物体ID対応に基づく）、位置RMSE、状態遷移イベントの検出遅延・取りこぼし率、グラフ陳腐化率（有効期限切れ主張の残存）。
- 「忠実度」はタスク成功より高感度な連続指標として、アンカリング層の改善検出に用いる。

### 7.2 反実仮想リプレイ
記録した同一観測列を異なる構成（ベースライン/アブレーション）に再生して対比較する。
- 効果: 物理再実行不要で高速、入力同一による対応のある検定（McNemar / Wilcoxon）、LLM応答キャッシュによる再現性とコスト削減。
- 「記録 → 多条件リプレイ → 対比較」を実験の基本単位とする。

### 7.3 劣化ノブと頑健性曲線
`configs/degradation/` でパラメータ化: ID読取失敗率、姿勢ノイズσ、オクルージョン率、観測遅延、矛盾観測率。点比較でなく**掃引曲線**で条件間比較し、ORの価値が立ち上がる動作領域を特定する。

### 7.4 メタモルフィック・テスト
意味保存変換（ラベル改名、同義語置換、スキーマ表層変更、言語切替）に対する回答不変性を検査し、「オントロジー構造への依拠」と「文字列表層一致による見かけの成功」を切り分ける。

## 8. 実験計画

### 8.1 比較条件
- **B0**: 生データダンプ直投入（オントロジー無し）。
- **B1**: ロボット個別スキーマ＋ツールのみ（共通オントロジー無し）。
- **OR-full**: フルスタック。
- アブレーション: `OR−identity`（同一性解決オフ）/ `OR−belief`（来歴・確信度オフ）/ `OR-sym`（記号のみ）/ `OR-vec`（ベクトルのみ）。

### 8.2 タスクスイート
| ID | 名称 | 概要 | 仮説 |
|----|------|------|------|
| T1 | 越境同一性 | ロボットAの観測物体をロボットBが操作。同一性解決が必須となる課題設計 | H2, H4 |
| T2 | 業務‐物理クエリ | 「受注#Nはどこか」等50問、真値照合で採点 | H6, H7 |
| T3 | 能力考慮計画 | 重量/リーチ/素材適性で誤選定が失敗に直結する割当課題 | H3 |
| T4 | 劣化頑健性 | 劣化ノブ掃引下での忠実度・成功率曲線 | H5 |
| T5 | オンボーディング | 合成ベンダースキーマの新ロボット統合。LLM支援マッピング vs 手書き | H1 |
| T6 | エピソード較正 | 故障注入率を能力台帳が経験から推定（キャリブレーション） | H3 |
| T7 | SOP検索 | オントロジー誘導検索 vs 素のベクトルRAG | H4 |

### 8.3 統計・再現性ポリシー
- LLM: モデルはスナップショット名で固定、temperature 0、全応答をディスクキャッシュ（キー: モデル×プロンプトハッシュ）。
- 各条件 20〜50 エピソード×複数シード。成否は McNemar、連続指標は Wilcoxon 符号順位、区間はブートストラップ。
- 乱数は単一シードから全コンポーネントへ派生注入。`exp run` の出力には構成ハッシュ・シード・モデル版を必ず焼き込む。
- 可能なら主要結果を第2のLLMモデルで再現確認（モデル依存性の切り分け）。

## 9. フェーズ計画と完了基準

| Phase | 内容 | 主要成果物 | 完了基準（exit criteria） |
|-------|------|-----------|--------------------------|
| **P0** | 基盤: 最小世界(1ロボット)、蒸留パイプライン、**真理グラフ＋忠実度メトリクス**、記録基盤 | C1,C4,C6,C8,C9の骨格 | 忠実度F1がノイズ0で>0.95、記録→リプレイで同一結果 |

| **P3** | 能力契約・故障注入・割当 | C2拡張、T3/T6 | 能力台帳のBrierスコアがエピソードと共に改善 |

各Phaseは独立に一本の検証結果（仮説×指標×曲線）を生む。途中打ち切りでも成果が残る構造を維持する。

## 10. 技術スタックと環境制約

- **ハード/OS**: Apple Silicon MacBook、macOS。GPUはMPSのみ（CUDA前提コード禁止）。
- **言語/管理**: Python 3.11+、`uv` でロックされた単一仮想環境。`pyproject.toml` を唯一の依存定義とする。
- **主要依存**: `mujoco`(>=3.x)、`pyoxigraph`、`pyshacl`、`rdflib`(TTL編集用)、`lancedb`(または`faiss-cpu`)、`open_clip_torch`(MPS)、`openai`、`pydantic`(全メッセージ/設定のスキーマ)、`numpy`/`pandas`/`scipy`、`typer`(CLI)。
- **外部通信は OpenAI API のみ**。視覚埋め込みはローカルCLIP（OpenAIは画像埋め込み非提供のため）。テキスト埋め込みはOpenAI、応答・埋め込みとも全キャッシュ。
- ミドルウェア: ROS不使用。`asyncio`＋ZeroMQ程度の軽量pub/sub。
- レンダリング: オフスクリーン低解像度（224px、CLIP入力に整合）。知覚周期は物理周期から分離（目安: 物理500Hz / 知覚2Hz）。
- 性能予算（目安）: 1エピソード(60秒シム相当)の記録 ≤ 実時間2倍、リプレイ1条件 ≤ 30秒、API費用は記録時に集中しリプレイはキャッシュヒットでほぼゼロ。

## 12. 成功基準と成果物

**プロジェクト成功の定義**: H1〜H7 の各仮説について、(a) 統計的裏付けのある肯定/否定/条件付きの結論、(b) それを生んだ再現可能なリプレイ一式、(c) 自動生成された図表付きレポート、の3点が揃うこと。仮説が棄却される結果も成果である（その場合は棄却条件の特定までを成果とする）。

最終成果物: ①再現可能な実験基盤（本リポジトリ）、②仮説別検証レポート群（`reports/`）、③頑健性曲線・知識効率（正答率/トークン）の横断分析、④研究報告ドラフトの素材一式。

## 13. リスク登録簿

| リスク | 影響 | 対応 |
|--------|------|------|
| 擬似VLAが実VLAの失敗分布を近似しない | H3結果の外的妥当性低下 | P5で小型実VLA(MPS)に差し替え主要結果の頑健性確認。限界として明記 |
| OpenAIモデル更新による結果漂移 | 再現性毀損 | スナップショット固定＋全応答キャッシュ＋第2モデル再現 |
| 同一性解決の難度がシムで過小評価 | H2の外的妥当性 | 劣化ノブを実機相当域まで掃引し曲線で外挿議論 |
| グラフ肥大による性能劣化 | 長尺実験の破綻 | 蒸留規律＋有効期限付き主張＋陳腐化率の常時監視 |
| macOS固有の描画/MPS問題 | 開発停滞 | オフスクリーン描画経路をP0で最初に固める。CUDA依存ライブラリの混入禁止 |
| 実験コードと評価コードの結合 | 評価の信頼性低下 | oracle(C8)はシム真値のみ参照し、ORコアへ依存しない一方向構造を厳守 |

## 14. 用語集（抜粋）

- **世界グラフ**: 来歴・確信度・時刻付き主張からなる動的ABox。全エージェントの共有信念。
- **真理グラフ**: シム内部状態から機械生成される完全な真値ABox。評価専用でORコアからは不可視。
- **忠実度**: 世界グラフと真理グラフの差分から算出する一致度指標群。
- **アンカリング**: 知覚データ・記号識別子・既存個体を束ねて単一IRIへ確率的に対応付ける処理。
- **能力契約**: ロボットが宣言するアフォーダンス・前提/効果・成功率統計。計画と実行の境界仕様。
- **アイデンティティ・スレッド**: 業務レコードから物理個体までの識別子参照連鎖。
- **劣化ノブ**: 知覚・通信の品質を操作する実験パラメータ群。
- **反実仮想リプレイ**: 記録済み観測列を別構成に再生して行う対比較。
- **CQ（コンピテンシー質問）**: オントロジーが答えられるべき質問集。仕様であり回帰テスト。
