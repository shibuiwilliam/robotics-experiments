## 1. H6 — 業務‐物理クエリ（T2, OR-full vs B1/B0）

実LLMエージェント3条件（同一観測列の反実仮想リプレイ・54問）:

| 条件 | 射程 | 正答率 | 総トークン | 正答率/1kトークン |

| B0（生ダンプ） | agent | 0.500 | 65,159 | 0.0077 |

- **オントロジーを使うエージェント（OR-full）が、生データ/個別スキーマのエージェント

  使って勝つ」という H6 本体の初実証である。
- 決定的上限（OR-reference 1.000）との差（0.833）は、LLM の推論・ツール使用の不完全性であり、
  オントロジー表現の限界ではない（ceiling と agent の射程差）。

## 2. H7 — トークン効率（オントロジー＝文脈圧縮）

- OR-full は **B1 より高精度（0.833 vs 0.407）かつ少トークン（109k vs 165k）** — オントロジーが
  異種スキーマの正規化済み意味を提供し、エージェントが生スキーマを解釈し直す冗長往復を省く。
- B0 は最少トークン（65k・全データを inline 投入）だが正答率 0.500 に留まる。OR-full は同等の
  トークン効率（0.0077）でより高い正答率を達成。**「少トークンで同等以上」を満たす**。

## 4. H1 — オンボーディング統合コスト（llm 支援 vs 手書き）

| 条件 | フィールド精度 | 人手修正行 | 検証合格率 |
|------|---------------|-----------|-----------|
| 手書き（ベースライン） | 1.000 | 10.75（全行記述） | 1.00 |
| **llm 支援（実LLM）** | **0.977** | **0.25** | 0.85 |
| heuristic（規則・ceiling） | 1.000 | 0.00 | 1.00 |

- 実 LLM 支援は、20 合成ベンダースキーマに対し **人手記述を 10.75行 → 0.25行へ圧縮**しつつ
  フィールド精度 0.977 を達成。ハブ&スポーク写像が新規ロボット統合コストを下げる（H1 支持）。
- heuristic が飽和（1.000）するのはファズ空間が規則射程に収まる設計のため（ceiling）。llm は
  規則外の異質スキーマにも一般化する点が agent 射程の価値。

| S | 仮説 | OR-full-llm | baseline-llm | 判定 |

## 4d. live 所見への設計的対処（follow-up・2026-06-17b）— S7 安全ガード / S5 ドメイン規制

§4c の honest な S5 null・S7 mixed 所見を**ただ報告するだけでなく**、それぞれに設計で応答し live で検証した。
両者とも真値非参照・`make scenario-verify-live-cache` で $0 再現。**新規 LLM 課金は ~$0.03**（S7 中難度 ~$0.01・
S5 架空規制 ~$0.02。S7 ガードは OR-full-llm のプロンプトを再利用＝キャッシュヒットで追加課金なし）。

### S7 ツール側エスカレーション・ガード（H4/H6・安全） — 安全保証は移植できる
S7 mixed の核心は「決定的 OR-full は低マージンを必ず確認(X5)へ委譲し誤配送0を**保証**するが、実 LLM は
プロンプト規則を確率的にしか守らず誤配送 0.054 を出す」。対処として、**確信度マージン < 閾値 の配送を
システムが機械強制で ESCALATE に上書きする安全ツール**（`OR-full-llm-guarded`・蒸留マージンのみ・真値非参照）
を追加した。OR-full-llm と同一プロンプトを使う（=キャッシュヒット・追加課金 0）。

| sep | 条件 | success | misdelivery | escalation |
|-----|------|---------|-------------|------------|
| 0.3（瓜二つ・最難） | OR-full-llm | 0.268 | **0.054** | 0.679 |
| | OR-full-llm-guarded | 0.000 | **0.000** | 1.000 |
| 0.6（中難度） | OR-full-llm | 0.643 | **0.018** | 0.339 |
| | **OR-full-llm-guarded** | **0.286** | **0.000** | 0.714 |
| | B0-llm | 0.000 | 0.000 | 1.000 |

- **結論**: 決定的版の安全（誤配送0）は**アーキテクチャ（ツール側強制）でエージェントに移植できる**。
  中難度 sep=0.6 ではガードが**誤配送を 0 にしつつ高マージンの自動配送（成功 0.286 > B0 の 0）を保つ**
  ＝「安全な自動化」。最難 sep=0.3 では全件委譲（成功0・誤配送0）で決定的 OR-full の保守挙動に一致。
- **含意**: 実 LLM の「自動化の上積み」(0.643/0.268) は**低マージンの危険な賭け**から来ており、誤配送0が要件の
  安全臨界用途では**プロンプト規則ではなくツール側のハード強制**が必要。OR の価値は「安全ツールの提供」を含む。

### S5 ドメイン固有規制の境界（H5） — 規範オントロジーの価値が立つ条件
S5 null は「LLM が一般常識で規制薬物→公共回避を知る」ため norm-map の上積みが消えた。**LLM 事前知識に無い
架空規制**（`reagent_zeta` は架空区画分類 `atrium` を通過禁止・常識的根拠なし）を置いた別世界
（`configs/world/s5_domain_norm.yaml`）で再検証:

| 条件 | violations | 解釈 |
|------|-----------|------|
| OR-full-llm（規範写像あり） | **0** | 架空規制を写像から知り atrium を回避 |
| B1-llm（規範写像なし） | **4** | 架空規制を知らず最短で atrium を通過＝違反 |

- **結論**: S5 null は**常識的規制に限った境界**であり、**規範オントロジーは LLM 事前知識に無いドメイン固有規制で
  価値が立つ**（OR-full-llm 違反0 vs B1-llm 違反4）。両世界を合わせると「OR の規範層が効く動作領域＝LLM が
  常識で覆えない規制」という**境界条件**が live で定量化された。

> **総括（follow-up）**: live の null/mixed は終点ではなく出発点だった。S7 は**安全をアーキで移植**し、S5 は
> **OR の価値が立つ規制の境界**を示した。いずれも「オントロジーがエージェントを助ける動作領域」を**より鋭く**
> 定めるもので、装置の信頼性（真値非漏洩・採点独立・$0 再現）は保たれている。

## 5. 第2モデル再現（モデル依存性の切り分け・2026-06-18・gpt-5.4-2026-03-05）

- **6/7 が model-independent**: 「オントロジーを使うエージェントが生データに勝つ」中核結論（H1/H2/H4/H5/H6/H7）は
  世代・容量の異なる第2モデルでも**同方向で再現**＝外的妥当性が強まった（PROJECT.md §13 リスク低減）。
- **S6 は model-DEPENDENT（重要・honest）**: 規制写像の**コスト優位**は第1モデルでは成立したが、より強い
  第2モデルでは**反転**（B0-llm 0.594 < OR-full-llm 1.375、両者とも高コスト誤り0）。強モデルは高コスト誤りを
  自前知識で回避でき、OR-full-llm の保守的委譲（escalation 0.46 vs 0.20）が逆にコスト増になる。**S5 null
  （LLM 常識が規制を吸収）と同型の現象がコスト次元で再現**。安全（高コスト誤り0）は両モデルで保たれ、
  反転するのは効率/自動化次元のみ。
- **含意**: OR の規範/規制オントロジーの価値は**モデル能力に依存**する — 弱いモデルでは規制写像がコストを
  下げるが、強いモデルでは事前知識が代替する（S5 null・S6 cost）。一方、同一性解決(S1)・信念調停(S2)・
  双対表現(T7/S1)・能力統合・identity thread・知識効率(H7) の優位は**モデル非依存**で頑健。これが
  「OR がエージェントを助ける動作領域」の最終的な地図。

> モデル依存で、強モデルでは S5 null と同型に消える。装置（真値非漏洩・採点独立・$0 再現）は全工程で保持。

### 5.1 S6 能力境界の精緻化（3 モデル: nano / mini / full・2026-06-19）

S6 の model-dependence を最弱 `gpt-5.4-nano-2026-03-17` で 3 点目を取り（~$0.01・16 episodes・$0 再現）、
規制オントロジーが効く能力境界を確定した。**価値は能力に対し単調ではなく中位スイートスポット（逆U字）**:

| モデル能力 | OR-full-llm | B0-llm | 規制写像の効果 |
|------------|-------------|--------|----------------|
| **nano**（最弱） | mean_cost 3.000・全件委譲 | 3.000・全件委譲 | **無効** — 弱すぎて確信を持って route できず両者全件委譲（map 以前の問題） |
| **mini**（中位） | **1.094**・誤り0 | 2.083・**高コスト誤り2** | **有効** — route はできるが、map 無しの B0 は高コスト品を誤レーン送り |
| **full gpt-5.4**（強） | 1.375・誤り0 | **0.594**・誤り0 | **冗長/有害** — B0 が自前知識で正しく route、OR-full の保守的委譲は純コスト |

- **含意**: OR の規範/規制オントロジーが agent のコストを下げるのは「**route する能力はあるが規制を自前知識で
  賄えない中位モデル**」に限られる。弱すぎる(nano)と route 自体ができず map が無意味、強すぎる(full)と
  自前知識が map を代替する（S5 null と同型）。＝**OR 規範層の ROI は対象 LLM の能力帯に依存**し、
  デプロイ判断は「使用モデルがこの中位帯か」で行うべき、という実務的示唆。
- 装置面: 3 モデルとも `make scenario-verify-live-cache` で $0 再現・真値非漏洩・採点独立を保持。

### 5.2 S8 キネティック層（H8）の能力境界（3 モデル: nano / mini / full・2026-06-27）

S8 のアクション型を 3 モデル（`gpt-5.4-mini` / `gpt-5.4-2026-03-05` / `gpt-5.4-nano-2026-03-17`・各 ~$0.25・
$0 再現）で実測した。**S6 と対照的に、H8 のキネティック便益は能力帯の全域で model-independent**:

| モデル能力 | OR-full-llm（完遂 / 安全違反 / 誤配送 / 監査 / 回復） | ベースライン |
|------------|------------------------------------------------------|--------------|
| **nano**（最弱） | 1.000 / 0 / 0 / 1.000 / 1.000 | 完遂0・誤配送1.0・監査0・回復0 |
| **mini**（中位） | 1.000 / 0 / 0 / 1.000 / 1.000 | 同上 |
| **full（2026-03-05）** | 1.000 / 0 / 0 / 1.000 / 1.000 | 同上 |

- **含意（S6 との対比が核心）**: S6 の規制ルーティングは「クエリに答える」課題で、価値が能力に**非単調**
  （中位スイートスポット）だった。S8 のアクション型は **安全・監査・可逆を LLM ではなく**アクション層**
  （送信基準のハード強制＋来歴付き custody＋決定的補償）が機械的に保証**し、共通オントロジーが正規化知識を

  ＝**キネティック層の保証はモデル能力に非依存**（PROJECT.md §13 モデル漂移リスクに対し最も頑健）。
- これは H8 の本質的主張の強い裏付け: 「オントロジーのアクション型はエージェントの世界変更を安全・監査
  可能・可逆にする」という保証は、**弱い LLM でも成立する**（規範/能力/所有の判断を LLM の知識に委ねず
  送信基準で機械強制するため）。S5 null・S6 非単調が「LLM 知識依存の境界」を示したのと対をなす知見。
- 装置面: 3 モデルとも cache ゲート（`test_s8_*`）で $0 再現・真値非漏洩・採点独立を保持。
