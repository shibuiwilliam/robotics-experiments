# シナリオ2：食品工場のアレルゲン交差汚染管理

| 項目 | 値 |
|------|-----|
| 主試金石 | **② 関係伝播**（接触イベントの推移閉包）。副次的に時間付き状態推論 |
| 中核仮説 | **H5**（信念管理：接触の見落とし下の頑健性）＋ 事象推論（時空間・事象オントロジー） |
| 提案タスクスイート | **T9 交差汚染追跡** |
| ORX縮約コスト | **小**（接触イベントの蒸留） |
| ステータス | 採用推奨（2番手・独自性の頂点） |
| 提案世界/実験 | `configs/world/s2_allergen.yaml` / `configs/experiments/s2_allergen.yaml`（未作成） |

## 1. 叙述

セントラルキッチンで、ピーナッツ含有製品を扱ったグリッパは、**洗浄イベントを経るまで**
アレルゲンフリーラインの製品に触れてはならない。

連鎖の例: グリッパ G が箱 A（ピーナッツ含有）に触れる → A をトレイ T に置く → T に箱 B が載る。
このとき汚染可能性は **G → A → T → B** とどこまで伝播したか。エージェントは出荷直前に
「箱 B はアレルゲンフリーとして出荷してよいか」を判定し、汚染経路上の個体を隔離・再洗浄へ回す。
途中で「洗浄」イベントが入ると、その対象（グリッパ/トレイ）の汚染状態はリセットされる。

## 2. なぜオントロジーが必要か（試金石への適合）

核心は、**汚染が「接触イベントの推移閉包」として定義される**ことにある。

- これは知覚単体（C4）でもDB単体（C3）でも答えられない。接触イベント**列の上での関係推論**そのもの。
- 試金石②（関係伝播）が業務の成否を直接握る、独創性の高い構図。
- さらに「洗浄」という**浄化イベントが状態をリセット**するため、時間付き状態推論（`orx-st:` 事象
  オントロジー＋ `orx-prov:observedAt`/`validUntil`）の検証にもなる。汚染は接触時刻以降・洗浄時刻
  までの有効区間を持つ時限的主張として表現される。

## 3. 反証可能な予言（オントロジー無しの失敗）

> **帰無仮説**: 接触イベント列の推移閉包を持たない構成は、間接接触（G→A→T→B の B）を**汚染と
> 判定できず**、危険な見逃し（false-negative＝汚染品をフリーとして出荷）を出す。

- **B0 / B1**: 「いま誰が何に触れているか」の単発観測は持てても、**過去の接触連鎖を辿る関係推論**が
  できない。直接接触は当てられても推移的汚染（2ホップ以上）で取りこぼす。
- **OR−belief**（来歴・確信度オフ）: 洗浄イベントによる失効や、接触見落とし時の確信度低下を扱えず、
  「いつ汚染が解除されたか」の時間推論が崩れる。劣化（接触見落とし率）下で急速に悪化。
- **OR-full**: 接触グラフの推移閉包＋洗浄失効で、汚染集合を正しく算出。
- 非対称コスト: false-negative（汚染見逃し）は法的・安全上の重大事故。recall を最優先指標とする。

## 4. ORXへの縮約

| 要素 | 縮約方法 |
|------|----------|
| 世界（C1） | 物体に**物質タグ** `material/allergen`（既存 `BoxConfig.material` を流用・拡張）。グリッパ・トレイを個体化 |
| 接触イベント | **シムの接触判定**（MuJoCo contact）から蒸留した `ContactEvent{a, b, t}` を C6 に記録（生データはグラフに入れない） |
| 洗浄イベント | `scripted` な `CleaningEvent{subject, t}`（対象の汚染主張を `validUntil=t` で失効） |
| オントロジー追加 | `orx-st:ContactEvent`, `orx-st:contacted`（推移的に解釈）, `orx-st:CleaningEvent`, `orx-st:contaminatedBy`。**提案** |
| 汚染推論 | SPARQL の連鎖クエリ＋アプリ側の推移閉包（重い推論器は使わない＝§6方針） |
| 触れるC | C1（接触）, C4/C5（接触の蒸留・個体化）, C6（イベント記録＋失効）, C7（出荷可否判定）, C8（真の推移閉包）, C10 |
| 劣化ノブ | **新規** `contact_miss_rate`（接触イベントの見落とし率）を sim/perception 側に追加し掃引（H5） |

## 5. タスク定義（採点）

- **入力**: 接触・配置・洗浄イベント列の記録（C9）。
- **判定**: 各出荷候補箱について「アレルゲンフリーとして出荷可か」の二値。
- **真値（C8 oracle）**: シム接触の**真の推移閉包**を機械計算し、各時点の真の汚染集合を導出。
  → 世界グラフが主張する汚染集合とトリプル単位で突合できる（**シミュレーション検証との相性が抜群**）。
- **採点**: 汚染集合の precision / **recall（最重要）** / F1、出荷可否の正答率、誤出荷（false-negative）件数。

## 6. 実験条件

| 条件 | 期待 |
|------|------|
| B0 / B1 | 直接接触のみ。2ホップ以上の推移汚染を取りこぼす（recall 低） |
| OR−belief | 洗浄失効・確信度を扱えず、劣化下で急悪化 |
| **OR-full** | 推移閉包＋失効で recall 高、誤出荷 ≈ 0 |

`contact_miss_rate` を 0→高 へ掃引した**頑健性曲線**で OR-full と OR−belief の乖離領域を特定（H5、
T4 と同じ装置）。

## 7. 指標

- 汚染集合の precision/recall/F1（トリプル採点）
- 誤出荷（false-negative）件数 — 非対称コストの主指標
- 頑健性曲線（contact_miss_rate × 条件）
- 洗浄後の汚染失効が正しく反映される時間精度（イベント検出遅延）

## 8. 既存資産との関係

- **T4（劣化頑健性）** の掃引ランナー・乖離領域検出（C10）と、**信念調停**（C6 の確信度×新しさ、
  TTL失効）をそのまま使える。汚染失効は TTL の自然な応用。
- 新規は「接触イベントの蒸留」と「推移閉包クエリ」、`contact_miss_rate` ノブ。

## 9. 実装メモ / コスト

- **小コスト**。MuJoCo の接触取得は既存 `SimWorld` に接触読み出しを足すだけ。推移閉包はアプリ側で
  幅優先探索（EL/QL軽量方針に沿う）。
- 独自性が最も高く、真理グラフ採点で「関係推論の正しさ」を定量化できる。**2番手で着手**。
