# ORX 検証シナリオ集

本ディレクトリは `SCENARIOS.md`（着想）を、各シナリオの**詳細定義**として落とし込んだものである。
各ファイルは「叙述 → なぜオントロジーが必要か → 反証可能な予言 → ORXへの縮約 → タスク定義 →
実験条件 → 指標 → 既存資産との関係 → 実装コスト」の共通テンプレートで記述する。

## オントロジー必要性の三つの試金石（SCENARIOS.md §冒頭）

シナリオが ORの検証に値するかは、次の少なくとも一つ（理想的には複数）が**業務の成否そのものを
握っている**かで判定する。多くの自動化シナリオはフラットなDB＋素朴なRAGで解けてしまい、ORの
反証にならない。

| ID | 試金石 | 定義 |
|----|--------|------|
| ① | **越境同一性** | 「同じモノ・コト」が複数システムに別々の姿で現れ、それを単一個体へ束ねないと業務が成立しない |
| ② | **関係伝播** | 観測事実から、関係を辿った推論（接触の推移・包含・由来）で初めて導ける帰結が意思決定を左右する |
| ③ | **規範と監査** | 「してよいか」「なぜそうしたか」を、規則と来歴に照らして機械的に説明できることが要求される |

## 設計規律：反証可能な予言（必須）

各シナリオには必ず「**オントロジー無しではどう失敗するか**」の予言を書く（SCENARIOS.md §末尾）。
予言が書けないシナリオは試金石を満たしておらず、検証しても条件間に差が出ない。予言は実験の
**帰無仮説**そのものであり、ベースライン条件（B0/B1）や該当アブレーション（OR−identity 等）が
構造的に失敗することを事前に宣言する。

## 採用順序の提案

**1 → 2 → 6**（SCENARIOS.md §横断比較）。

1. **シナリオ1（ロット回収）**: 既存ミニ倉庫＋T1/T2の自然な業務文脈化。追加コストがほぼゼロで、
   アイデンティティ・スレッド（H6）と越境同一性（H2）の最も純粋な検証。
2. **シナリオ2（アレルゲン）**: 「関係伝播」というORでしか語れない価値を、真理グラフ採点付きで
   トリプル単位に示せる独自性の頂点。
3. **シナリオ6（リサイクル）**: 双対表現（H4）の優位を OR-sym / OR-vec アブレーションで最も鮮明に
   分離できる設計。

シナリオ5（規範層）は研究的に最も野心的だが、新オントロジー層（deontic制約）の実装を伴うため
Phase 5 以降の拡張に位置づける。
