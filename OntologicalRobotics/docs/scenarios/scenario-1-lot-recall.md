# シナリオ1：ロット回収（リコール）下の倉庫オペレーション

| 項目 | 値 |
|------|-----|
| 主試金石 | **① 越境同一性**（＋①の派生として進行中タスクの再評価） |
| 中核仮説 | **H2**（同一性解決）, **H6**（アイデンティティ・スレッド）。横断的に H7（トークン効率） |
| 提案タスクスイート | **T8 ロット回収**（T1/T2 機構を再利用） |
| ORX縮約コスト | **最小**（既存ミニ倉庫世界＋「ロット属性＋割込み指示イベント」） |
| ステータス | 採用推奨（1番手） |
| 提案世界/実験 | `configs/world/s1_lot_recall.yaml` / `configs/experiments/s1_lot_recall.yaml`（未作成） |

## 1. 叙述

平常運転中の物流倉庫に割込み指示が飛び込む。

> 「ロット番号 **L-2024-318** の製品に異物混入の疑い。即時隔離せよ。」

対象ロットに属する箱は、世界の各所に散らばっている:

- **棚に在庫**として静置されているもの
- **アームが把持中**のもの（搬送タスク進行中）
- **AGV/モバイルベースが搬送中**のもの
- すでに**ピッキング済みで出荷待機**のもの（受注に割当済み）

エージェントは (a) どの物理個体が回収対象ロットに属するかをリアルタイムに逆引きし、(b) 進行中の
搬送タスク群と回収指示の衝突を検出し、(c)「この搬送タスクの対象は回収対象ロットか」を**計画の
途中で再評価**して、対象個体を隔離ゾーンへ振り向ける。

## 2. なぜオントロジーが必要か（試金石への適合）

オントロジーが不可欠になる瞬間は、**「ロット」という業務概念（WMSのレコード）と「いま物理空間に
存在する個々の箱」（各ロボットの観測）を結ぶ参照連鎖を、リアルタイムに逆引きするとき**である。

```
Lot(L-2024-318) ──orders/contains──▶ Sku ──ShippingInstruction──▶ barcode
                                        └─ hasIdentifier ─▶ 物理個体(IRI) ─ inZone ─▶ 現在位置
```

試金石①（越境同一性）が業務の成否を直接握る。把持中・搬送中の箱は「いまどこか」「どの受注の
どのロットか」が、知覚（C4/C5）と業務（C3）のどちらか単独では決して埋まらない。

## 3. 反証可能な予言（オントロジー無しの失敗）

> **帰無仮説**: 生データダンプ方式（B0）は「把持中の箱がどの受注のどのロットか」に答えられず、
> ロット回収の**完全性（recall）が構造的に頭打ちになる**。

- **B0**（最新観測JSON＋業務CSVを文脈投入）: 箱の物理個体IDと受注/ロットを結ぶ参照連鎖を持たない
  ため、棚の在庫（バーコード可読）は当てられても、把持中・搬送中・ID読取失敗中の個体を取り
  こぼす。→ 回収 recall が低い。
- **B1**（個別スキーマ＋ツール、共通オントロジー無し）: ベンダー毎の語彙で「ロット」を横断
  結合できず、結合ロジックを人手で書いた分だけ部分的に当たるが、越境同一性が必要な個体で失敗。
- **OR−identity**（同一性解決オフ）: 同一個体が複数トラックに分裂し、回収判定が二重計上/取りこぼし。
- **OR-full**: アイデンティティ・スレッドで逆引きが閉じ、recall ≈ 1.0 を期待。

予言が外れる（B0でも高recall）なら、その世界は試金石①を満たすほど同一性が難しくない設計。

## 4. ORXへの縮約

| 要素 | 縮約方法 |
|------|----------|
| 世界（C1） | 既存 `t2_warehouse` を流用。棚＋搬送域＋**隔離ゾーン `quarantine`** を追加 |
| ロット属性 | `BoxConfig` に `lot: str` を追加（複数箱が同一ロットを共有）。WMS生成器が受注↔ロットを種付け |
| 割込みイベント | `scripted_moves` と同形の `recall_event {at_time, lot}` を実験定義に追加（進行中の搬送と時間衝突させる） |
| 進行中タスク | C2 スキルで搬送中の箱を作る（slide搬送＝把持/搬送中の状態を演出） |
| オントロジー追加 | `orx-biz:Lot`（情報的実体）、`orx-biz:inLot`（Sku/Order→Lot）、`orx-biz:lotNumber`。**提案** |
| 触れるC | C3（ロット種データ）, C5（同一性）, C6（業務写像）, C7（再評価ループ）, C8（採点）, C10 |
| 劣化ノブ | `id_read_failure_rate`（搬送中の読取困難を再現）で recall を掃引 |

## 5. タスク定義（採点）

- **入力**: 平常運転の記録（C9）＋ 時刻 `t_recall` での回収指示（対象ロット）。
- **決定**: 回収対象と判定した物理個体IRIの集合 `R̂`、および各個体を隔離ゾーンへ送る指示。
- **真値（C8 oracle）**: シム真値で対象ロットに属する全箱の集合 `R*`（隔離されたか否かも真値で判定）。
- **採点**: 集合 `R̂` vs `R*` の **precision / recall / F1**、隔離成功率、進行中タスクの**再計画回数**、
  決定までのレイテンシ。T2形式の業務‐物理クエリ（「ロットXはいまどこか」）も併設可。
- **メタモルフィック**: ロット番号の改名・別表記でも回答不変（文字列表層一致でなく構造依拠の確認）。

## 6. 実験条件

| 条件 | 期待 |
|------|------|
| B0 生データダンプ | recall 低（把持/搬送中を取りこぼす） |
| B1 個別スキーマ | recall 中（人手結合分のみ） |
| OR−identity | F1 劣化（分裂/二重計上） |
| **OR-full** | recall ≈ 1.0、再計画が正しく発火 |

対応のある反実仮想リプレイ（同一記録を全条件で再生）＋ McNemar（回収成否）/ Wilcoxon（F1）。

## 7. 指標

- 回収集合の precision / recall / F1（主指標）
- 隔離タスク成功率、再計画回数（割込み対応の質）
- 正答率/トークン（H7）、決定レイテンシ
- 忠実度（オラクル）: 回収判定はトリプル単位で真理グラフと突合できる

## 8. 既存資産との関係

- **T1（越境同一性）** の同一性解決機構（C5、D1スコア）と、**T2（業務‐物理クエリ）** の
  アイデンティティ・スレッド（バーコード結合）をほぼそのまま再利用できる。
- 追加は「ロット」概念と「割込み再評価」のみ。T8 は T1+T2 の業務文脈化と位置づけられる。

## 9. 実装メモ / コスト

- **最小コスト**。`orx-biz:Lot` の TBox 追記＋ SHACL（ロットは情報的実体）＋ WMS生成器のロット
  種付け＋ 割込みイベントのランナー対応で成立。
- 段階: 既存 T1/T2 が緑なので、**最初に着手すべきシナリオ**。新規オントロジー層は不要。
