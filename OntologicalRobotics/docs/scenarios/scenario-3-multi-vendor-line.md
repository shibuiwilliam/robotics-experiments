# シナリオ3：多ベンダー製造ラインの動的段取り替えと故障時再割当

| 項目 | 値 |
|------|-----|
| 主試金石 | **能力・統合**（語彙の違うベンダー仕様を越えた能力判定） |
| 中核仮説 | **H1**（統合コスト／オンボーディング）, **H3**（能力契約）。発展で H3 較正（T6） |
| 提案タスクスイート | **T10 動的段取り替え**（T3/T5/T6 を業務文脈化） |
| ORX縮約コスト | **小**（T3/T5 の文脈化） |
| ステータス | 候補 |
| 提案世界/実験 | `configs/world/s3_multi_vendor.yaml` / `configs/experiments/s3_multi_vendor.yaml`（未作成） |

## 1. 叙述

ベンダーA の6軸アーム、ベンダーB の協働ロボット、ベンダーC の AGV が混在するラインで、
品種切替（段取り替え）指示が来る。新品種は**重量と把持面（素材）の条件が異なる**。さらに作業の
途中で**アーム1台が故障**し、進行中の工程を残存機体へ再割当しなければならない。各機体の観測・
能力記述はベンダー毎に**語彙も単位も構造も異なる**。

## 2. なぜオントロジーが必要か（試金石への適合）

オントロジーが不可欠になる瞬間は、**作業指示書（文書）に書かれた工程要求を能力契約と突き合わせ、
「この工程をいま実行できる機体はどれか」を語彙の違うベンダー仕様を越えて判定するとき**である。

- 能力オントロジー（H3）の主戦場: 工程要求（重量範囲・把持面・作業領域）↔ 各機体の能力契約
  （`orx-cap:Capability`：declaredPayloadKg / reach / materialTag 別成功率）を共通語彙で照合。
- オンボーディングコスト（H1）の主戦場: スキーマ・ファジングで「**ベンダーD参入**」を再現すれば、
  T5（マッピング自動生成）がそのまま業務文脈を持つ。
- 故障注入器を「**経年劣化で成功率が下がる機体**」として演じさせれば、能力台帳の較正（T6）が
  予知保全的な意味を帯びる。

## 3. 反証可能な予言（オントロジー無しの失敗）

> **帰無仮説1（H3）**: 能力を見ない割当（round-robin / 最近傍）は、新品種の重量・素材条件を満たさ
> ない機体に工程を振り、成功率が頭打ちになる。
> **帰無仮説2（H1）**: 共通オントロジー無し（B1）では、ベンダーD参入時にマッピングを人手で全行
> 書く必要があり、統合所要時間・人手修正行数が支援生成（T5）より大きい。

- **round-robin**（能力無視）: 既に T3 で capability 0.968 vs round-robin 0.625 を実測済み。段取り
  替え後の新条件で差はさらに開く想定。
- **故障時**: 能力契約が無いと、残存機体の中から実現可能な機体を語彙横断で選べず再割当に失敗。
- **OR-full（能力契約＋台帳）**: 工程要求と能力を共通語彙で照合し、故障後も適格機体へ再割当。

## 4. ORXへの縮約

| 要素 | 縮約方法 |
|------|----------|
| 世界（C1） | 既存 `t3_capability` を拡張。3ベンダー相当のロボット（異なる payload/reach/material プロファイル） |
| ベンダー異質性 | 各機体に別ベンダースキーマ（`vendor_arm_a` / `vendor_mobile_b` ＋新規）。観測も能力記述も異形 |
| 段取り替え | 実験定義に `setup_change_event{at_time, new_product_spec}`（重量・素材条件が変わる） |
| 故障 | C2 故障注入器を時間で劣化させる（`base_success` を `at_time` 以降に低下）→ T6 較正が追従 |
| 新ベンダー参入 | C1 スキーマ・ファジング（`generate_fuzz_spec`）＋ `orx onboard`（T5） |
| 触れるC | C1, C2（劣化）, C5/C6（能力台帳）, C7（計画・再割当）, C8, C10。`orx onboard`（T5） |

## 5. タスク定義（採点）

- **入力**: 段取り替え指示（新品種スペック）＋ 進行中工程 ＋ 故障イベント。
- **決定**: 各工程→機体の割当、故障後の再割当。
- **真値（C8 oracle）**: 各 (機体, 工程) の真の成功率（C2 真値プロファイル）から最良割当を導出。
- **採点**: 割当正答率（真の最良に対する許容内選択）、再計画回数、工程完遂率、台帳 Brier（較正）。
- **オンボーディング**: ベンダーD のマッピング自動生成精度・人手修正行数・統合所要時間（T5）。

## 6. 実験条件

| 軸 | 条件 |
|----|------|
| 割当（H3） | `round-robin` vs `capability`（既存 T3 条件） |
| 統合（H1） | `handwritten` vs `heuristic` vs `llm`（既存 T5 条件） |
| 較正（T6） | 故障劣化の前後で台帳 Brier 信頼性項の追従 |

## 7. 指標

- 割当正答率・再計画回数・工程完遂率（H3）
- Brier 信頼性項の改善曲線（T6、劣化への追従）
- フィールド精度・人手修正行数・統合所要時間（H1 / T5）

## 8. 既存資産との関係

- **T3/T6（能力契約・較正）** と **T5（オンボーディング）** をほぼそのまま結合する業務文脈化。
  新規アルゴリズムはほとんど不要で、世界・イベント・スケジューリングの組み立てが主。

## 9. 実装メモ / コスト

- **小コスト**。既存 T3/T5/T6 の機構を 1 つの製造ラインの物語に束ねる。
- 「段取り替え＋故障＋新ベンダー参入」を 1 エピソードに同居させると、H1・H3・T6 を同時に
  exercise できる統合デモになる。
