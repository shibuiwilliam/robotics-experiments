## 0. エグゼクティブサマリー

### 0.1 検証するもの

世界モデル（WM：センサ観測から潜在状態を学習し、将来を予測する非記号的モデル）とオントロジー（業務対象・関係・制約を宣言的に定義した記号的モデル）を、双方向の接地層（Grounding Layer）で結合し、物理世界の状態と業務記録の状態を常時突き合わせる「知的データ空間」を構築する。技術的な核心は両者を一つのモデルに統合することではなく、接地層の写像 α（潜在→記号）と γ（記号→潜在）を学習可能にし、両者の整合性を定量化する点にある。

### 0.2 中心となる問い

1. 潜在状態から業務オントロジーの事実（存在・同一性・位置・状態・関係）を、業務利用に耐える精度で復号できるか。
2. 業務上の文脈（計画・制約・スケジュール）を条件として与えると、WMの予測精度と有効ホライズンは改善するか。
3. 「潜在で進めてから記号化した結果」と「記号化してから業務プロセスで進めた結果」の差（整合性ギャップ ε）は、物理と記録の乖離・プロセス逸脱・オントロジー欠落を検知する指標として機能するか。
4. これらを組織横断のデータ空間として運用するとき、生データではなく「出所と不確実性付きの接地済み主張・予測」を交換単位にすることは成立するか。

### 0.3 進め方

| フェーズ | 期間 | 環境 | 主眼 |
|---|---|---|---|
| P0 基盤確立 | M1–M3 | シミュレーション（Isaac Sim等） | 接地演算子 α/γ と指標 ε の実装、E2Eパイプライン、合成シナリオ |
| P1 実環境検証 | M4–M8 | 実サイト限定区画（代替：ミニチュア倉庫） | 接地精度、乖離検知、条件付き予測、制約付き計画 |
| P2 拡張・連合 | M9–M12 | 実サイト＋模擬第二拠点 | 反実仮想、概念発見、連合ツイン、オペレータ評価、本番化判断 |

### 0.4 成功の定義（要約）

- ゲートG1（M8末）：アンカー時刻における位置事実のF1 ≥ 0.90、注入した未スキャン移動の検知率 ≥ 90%（誤報 ≤ 2件/日）、記号条件付けによる60秒先予測誤差の改善 ≥ 20%。
- ゲートG2（M12末）：反実仮想予測のKPI相対誤差 ≤ 15%、拠点間で共有した予測の較正誤差ECE ≤ 0.05、オペレータの例外解決時間 ≥ 30%短縮。

### 0.5 体制と規模（仮置き）

コアチーム約7名（うち専任4名）、現場協力者2–3名。費用は人件費を除き概算で機材1,000–1,800万円、計算資源（12か月）600–1,200万円【要精査】。詳細は7章。

## 1. 背景・目的・スコープ

### 1.1 背景

- 業務システム（WMS/MES/ERP）が保持する「記録上の世界」と、センサが捉える「物理的な世界」は常にずれる。未スキャンの移動、誤った棚入れ、遅延したイベント登録、担当者の暗黙的な段取り変更などが原因で、記録は現実の遅れた近似にとどまる。
- 従来のデジタルツインは、CADレイアウトと離散事象シミュレーションを中心とし、現実の観測から自律的に更新される仕組みが弱い。ルールは人が書き、物理はシミュレータが仮定し、両者の乖離は人が発見する。
- 近年の世界モデル（映像から潜在状態と動態を自己教師ありで学習し、潜在空間で計画まで行うモデル群）は、物理世界の「次に何が起きるか」を観測から学習できる水準に達しつつある。一方でその表現は無名・非記号的であり、業務上の意味（この荷物はどの出荷指示に紐づくか、この配置は規則違反か）を持たない。
- データ空間（IDS/Gaia-X/Catena-X、国内ではウラノス・エコシステム）は、組織間でのデータ主権と共有語彙を整備しつつあるが、交換されるのは静的なデータであり、予測や物理状態の信念は扱われていない。

### 1.2 目的

1. WMとオントロジーを接地層で結ぶアーキテクチャの技術的成立性を、定量指標で示す。
2. 物理と記録の乖離を、人手ではなく整合性ギャップ ε の監視で検知できることを示す。
3. 業務の問い（WHAT-IF）を物理の予測に翻訳して答える経路を実証する。
4. 本番化の可否を判断するための、性能・コスト・運用・ガバナンス上の根拠を得る。

### 1.3 スコープ

含むもの
- 倉庫1区画（200–400 m²程度【要確認】）の物理観測（固定カメラ、RFID/バーコードイベント、扉・秤・PLC信号、可能なら車両テレメトリ）。
- 当該区画に関するWMS/EPCISイベントの取得（読み取りのみ。書き込みは行わない）。
- 上記を対象としたWM、オントロジー、接地層、乖離台帳、WHAT-IFクエリ、ダッシュボードの試作。
- 模擬第二拠点（シミュレーションまたは別区画）との連合検証。

含まないもの
- 業務システムへの自動書き戻し、自動指示出し、ロボットの直接制御（計画結果は助言・可視化に留める）。
- 区画外・拠点全体への拡張、全社オントロジーの整備。
- 個人の行動評価（人物は匿名化した「作業者」個体としてのみ扱い、個人識別は行わない）。

## 2. 検証対象コンセプト

### 2.1 アーキテクチャ（5層）

| 層 | 責務 | 主な構成要素 |
|---|---|---|
| 業務システム | 記録上の真実の保持、指示の発行 | WMS/WES、EPCISイベント、オーダー、作業割当 |
| オントロジー層（記号ツイン） | 継続体（物・場所・組織・契約・制約）の定義、事実の格納、制約検査 | 上位オントロジー（BFO/IOF）、EPCIS 2.0、AAS、SOSA/SSN、PoC拡張、RDFストア、SHACL |
| 接地層 | α：潜在→記号（意味プローブ）、γ：記号→潜在（条件付け）、整合性検査、乖離台帳、同一性解決 | 学習器、微分可能推論、台帳DB |
| 世界モデル層（潜在ツイン） | 生起体（過程・動態）の学習と予測、潜在空間での計画 | 視覚エンコーダ、物体中心表現、潜在動態モデル、階層化、不確実性推定 |
| 物理世界 | 観測とアンカーイベントの供給 | カメラ、RFID/バーコード、扉・秤、PLC（OPC UA）、車両テレメトリ |

データ空間層（連携・主権・利用制御）は上記を横断し、組織間で「接地済み主張と予測」を交換する。

### 2.2 形式的定義とPoCで測る量

- Z：WMの潜在状態空間。z_t ∈ Z は時刻 t の潜在状態（物体中心スロットの集合として実装）。
- S：オントロジーの公理（TBox）と整合するインスタンス集合（ABoxスナップショット）。s_t ∈ S。
- f: Z × A → Z：WMの動態。行動 a（車両の移動指令、コンベア速度など。観測できない場合は空）に条件付けられる。
- F: S × E → S：業務プロセスの遷移。イベント e（EPCISのObjectEvent/AggregationEvent等）による記録の更新。
- α: Z → Δ(S)：接地（抽象化）。潜在から事実集合の確率分布を出す。
- γ: S → Z：条件付け（具体化）。記号的文脈を潜在に埋め込む。
- 整合性ギャップ：ε_h = E_t[ d( α(f^h(z_t)), F^h(α(z_t)) ) ]。ホライズン h の予測において、「潜在で進めてから記号化」と「記号化してから業務遷移」の差。d は事実集合間の距離（付録A）。
- アンカー：外部から真値として扱える離散イベント（RFIDゲート通過、バーコードスキャン、秤の計量確定、扉開閉、PLC信号）。アンカー時刻 t_a では s_{t_a} の一部が確定する。

ε の分解と切り分け

| ε の発生源 | アンカー時刻での挙動 | 対応 |
|---|---|---|
| (1) 知覚・接地の誤り | アンカーで α の出力が真値と食い違う | 接地層の再学習、センサ配置見直し |
| (2) プロセス不遵守 | α はアンカーと一致するが F の予測と食い違う | 乖離台帳へ登録、業務側で確認 |
| (3) オントロジーの不完全性 | 残差が特定の潜在領域に集中し、既存の記号で説明できない | 概念発見ループへ |

### 2.3 用語

| 用語 | 定義 |
|---|---|
| 意味プローブ | z_t からオントロジー型付きの主張（存在・型・位置・状態・関係）を出力する学習ヘッド群 |
| 信念KG | 確信度・出所・有効時刻を付与した事実（RDF-star）を格納するグラフ |
| 乖離台帳 | 物理ツインの信念と記録ツインの主張の不一致を、解決状態と共に保持する台帳 |
| WHAT-IFクエリ | 介入（do(...)）を含む予測質問。オントロジー個体への介入を潜在への介入にコンパイルする |
| 概念発見ループ | 説明できない予測残差から新概念候補を生成し、人の承認でオントロジーに追加する仕組み |
| 遮蔽（シールド） | 計画候補を記号化してSHACL検証し、違反する候補を除外する機構 |

## 3. 検証仮説と成功基準

各仮説について、指標の定義、目標値（Go/No-Go閾値）、測定方法、実施段階を定める。指標の数式は付録Aに示す。

### 3.1 仮説一覧

| ID | 仮説 | 主指標 | 目標値 | 段階 |
|---|---|---|---|---|
| H1 | 潜在状態から業務事実を高精度に復号できる | 位置事実F1（アンカー時刻）、型分類精度、ID切替率 | F1 ≥ 0.90、型精度 ≥ 0.95、ID切替 ≤ 0.05回/物体・時間 | P0/P1 |
| H2 | 記号条件付けはWMの予測を改善する | 条件付け有無の予測誤差比、有効ホライズン H* | 60秒先誤差 20%以上改善、H* が1.5倍以上 | P0/P1 |
| H3 | 整合性ギャップ ε はプロセス逸脱の検知指標として機能する | 注入ドリフト検知のAUROC、平常時 ε の安定性 | AUROC ≥ 0.85、平常時 ε の日次変動係数 ≤ 0.2 | P1 |
| H4 | 物理と記録の乖離を自動検知できる | 検知率、誤報数、検知遅延 | 検知率 ≥ 90%、誤報 ≤ 2件/日、遅延中央値 ≤ 60秒 | P1 |
| H5 | オントロジー制約を計画のハード制約として保証できる | 違反率、性能損失 | 違反0（シールド有）、スループット低下 ≤ 5% | P1 |
| H6 | WHAT-IFの反実仮想予測は実測と整合する | 予測KPIの相対誤差、区間被覆率 | 相対誤差 ≤ 15%、90%予測区間の被覆率 ≥ 80% | P2 |
| H7 | 未知の概念を残差から発見できる | 注入概念の候補上位5への出現率 | 3種中2種以上 | P2 |
| H8 | 拠点間で予測を安全に交換できる | 較正誤差ECE、潜在復元攻撃の成功度 | ECE ≤ 0.05、復元画像SSIM ≤ 0.3、人物再識別 ≤ チャンス率×1.2 | P2 |
| H9 | オペレータの例外処理が改善する | 例外解決時間、訂正反映率、主観評価 | 時間 ≥ 30%短縮、反映率 ≥ 95%、SUS ≥ 70 | P2 |
| N1 | 非機能要件を満たす | E2E遅延、可用性、コスト | 観測→信念KG更新 ≤ 1秒、稼働率 ≥ 99%（営業時間）、区画あたり月額計算コストの試算提示 | P1/P2 |

### 3.2 各仮説の詳細

H1 接地精度
- 対象事実：`存在(物体)`、`型(物体, クラス)`、`位置(物体, ゾーン/棚)`、`状態(物体, {入荷待ち, 検品済, 保管中, ピッキング中, 出荷済})`、`関係(物体, 集約先パレット)`。
- 真値：アンカーイベント（スキャン・RFID・秤）で確定する事実を正、P1では加えて1日2回の棚卸し目視を正とする。
- 測定：アンカー時刻の直前1秒の α 出力と真値を照合。遮蔽（棚裏、人物による隠蔽、積み重ね）条件を別集計。
- 目標に届かない場合の判断：F1 ≥ 0.80 なら改善余地ありとして継続、0.80未満ならセンサ配置・エンコーダ選定を再検討しP1を1か月延長。

H2 記号条件付けの予測価値
- 比較条件：(a) 条件なし、(b) 静的文脈のみ（レイアウト、ゾーン制約）、(c) 動的文脈（オーダー、作業割当、到着予定）まで。
- 誤差：潜在空間誤差（予測潜在と実潜在のコサイン距離）と記号空間誤差（α で復号した事実集合の距離 d）の両方を報告。
- 有効ホライズン H*：記号空間誤差が閾値 τ（付録A）を超えるまでの最大ホライズン。

H3 整合性ギャップ
- 平常時 ε_h（h = 10秒, 60秒, 5分, 30分）の分布を2週間分で推定し、管理限界を設定。
- ドリフト注入：作業手順の変更（検品位置の変更、ピッキング順序の変更）を業務側と合意して実施し、ε の応答を計測。

H4 乖離検知
- 注入する乖離の型：未スキャン移動、誤棚入れ（記録と異なる棚）、誤スキャン（別物体のラベル）、遅延登録（30分以上後の登録）、幽霊在庫（記録にあるが物理にない）。各型10件以上、合計50件以上。
- 検知の定義：乖離台帳に該当エントリが生成され、対象物体と型が正しいこと。

H5 制約付き計画
- 対象：AGV/フォークリフトの経路と一時置き場の選定（助言のみ、実行はしない）。P0のシミュレーションで実行まで行う。
- 制約例：進入禁止ゾーン（人物在室中）、危険物クラスの隣接禁止、棚容量、賞味期限順（FEFO）。

H6 反実仮想
- 介入例：コンベア速度の変更、ピッキング担当の人数変更、一時置き場の位置変更。
- 手順：介入前にWHAT-IFで予測KPI（待ち行列長、処理時間、動線長）と予測区間を記録し、業務側と合意の上で介入を実施、実測と比較。実施できない介入はシミュレーション（P0で較正済み）で代替し、その旨を明記する。

H7 概念発見
- 注入：新しい荷姿（例：長尺物）、新しい工程（例：再検品）、新しい一時置き場の運用。オントロジーには未登録のまま2週間運用。
- 判定：残差クラスタから生成された候補（LLMによる命名と説明付き）の上位5件に該当概念が含まれるか。

H8 連合
- 構成：本サイトと模擬第二拠点（P0のシミュレーション環境を「別組織」として運用）。共有語彙（EPCIS 2.0 + PoC拡張）で予測（到着予定、在庫状態）を交換。
- 漏洩評価：共有する潜在表現に対して、復元攻撃（潜在→画像のデコーダ学習）と人物再識別攻撃を実施。

H9 オペレータ評価
- 対象者：現場リーダー・作業者5名以上。従来手順（記録と現物の目視突合）と乖離台帳ダッシュボードの比較。
- 指標：模擬例外10件の解決時間、訂正の反映確認、SUS（System Usability Scale）。

### 3.3 総合判定

| ゲート | 時期 | 通過条件 |
|---|---|---|
| G0 | M3末 | シミュレーションでH1、H2、H5の目標達成。E2Eパイプラインが遅延目標を満たす。P1の現場前提（A1–A7）が確定 |
| G1 | M8末 | 実環境でH1、H2、H3、H4の目標達成（H5はシミュレーション実績で可）。N1の遅延・可用性達成 |

未達の場合は、原因分析（ε の分解に基づく）と改善案を添えて1か月の延長を1回まで認める。2回目の未達で当該仮説は「不成立」として記録し、スコープを縮小して継続するか中止する。

### 5.2 世界モデル層（C2/C3）

入力
- カメラ4–8台の映像（15fps）。エッジで各フレームから特徴量（例：パッチ埋め込み）を抽出し、生映像はエッジ内に留める。
- アンカーイベント、車両テレメトリ、PLC状態（行動 a および観測補助として）。
- γ からの条件ベクトル（5.4）。

表現
- 視覚エンコーダ：自己教師あり映像モデル（V-JEPA系）を凍結して使用し、区画データで軽量アダプタを追加学習。比較対象としてDINO系画像特徴を用いる。
- 物体中心表現：slot attentionでフレームごとに K 個のスロット（K = 64【要調整】）を得る。各スロットにオントロジー型（パレット、ケース、車両、作業者、設備、不明）の型ヘッドを持たせ、型付きスロットとして扱う。
- 多視点統合：カメラごとのスロットを、キャリブレーションで得た床面座標に投影して統合する。

動態
- 潜在動態モデル：スロット集合と条件ベクトルを入力とするTransformerで z_{t+1} を予測。行動 a（車両指令、コンベア速度）は利用可能な場合に条件付け。
- 時間分解能：物理層は 1/15秒〜1秒（フレーム間引きで調整）。フロー層（C3）は1分単位で、信念KG上の到着・滞留・処理を予測する。
- 事象境界：オントロジー上のイベント（棚入れ完了、検品完了など）を境界として、階層WMの上位遷移を学習する（境界の教師あり化）。
- 不確実性：動態モデルのアンサンブル（5本）と潜在分散の両方で推定し、α の確信度と予測区間に反映。

学習
- P0：シミュレーション映像（100時間相当）で事前学習。真値付きのため α を教師ありで学習可能。
- P1：実サイト映像（2週間、営業時間で約150時間）で自己教師あり適応。α はアンカー自己教師（アンカー時刻の真値のみで学習）を主とし、少量の人手ラベル（棚卸し時の目視）を補助とする。
- 損失：予測損失（潜在）、接地損失（アンカー時刻）、制約損失（C6から、違反確率に対する罰則）、同一性一貫性損失（IDの時間的連続）。重みはP0で決める。
- 再学習：週次。評価セットに対する退行を検知したら前版へ戻す。

計画（H5用）
- 潜在空間MPC（MPPI）。候補軌道を α で記号化し、C6のSHACL検証で違反候補を除外（シールド）。出力は助言としてダッシュボードに表示するのみ。P0では模擬AGVで実行まで行う。

### 5.3 オントロジー層（C8）

構成
- 上位：BFO（継続体／生起体の区別）と IOF Core（産業オントロジー基盤）。
- ドメイン：EPCIS 2.0（イベント、ビジネスステップ、ディスポジション、ロケーション）、GS1 CBV、SOSA/SSN（観測・センサ）、AAS（設備）、ISA-95（一部：作業指示、設備階層）、PROV-O（出所）。
- PoC拡張（名前空間 `gt:`）：

| クラス／プロパティ | 定義 |
|---|---|
| `gt:Belief` | 接地により得られた主張。`gt:confidence`（0–1）、`gt:source`（WM/anchor/human/record）、`gt:validFrom/validTo`、`gt:transactionTime` を持つ |
| `gt:Anchor` | 真値として扱う離散イベント。`gt:anchorType`（rfid/scan/scale/door/plc） |
| `gt:Discrepancy` | 物理信念と記録主張の不一致。`gt:discrepancyType`、`gt:severity`、`gt:status`（open/confirmed/resolved/dismissed）、`gt:resolution` |
| `gt:Zone` / `gt:Slot` | 区画内のゾーンと棚位置。`gt:capacity`、`gt:allowedClass`、`gt:forbiddenAdjacentClass` |
| `gt:LatentRef` | 信念に対応する潜在スロットの参照（モデル版、スロットID、時刻）。潜在自体は格納しない |
| `gt:Intervention` | WHAT-IFの介入。`gt:target`、`gt:property`、`gt:value`、`gt:horizon` |
| `gt:ConceptCandidate` | 概念発見で生成された候補。`gt:evidenceCluster`、`gt:proposedLabel`、`gt:reviewStatus` |

時間モデル
- バイテンポラル：有効時間（世界でその事実が成り立っていた時間）と処理時間（システムがそれを知った時間）を分離。乖離の「遅延登録」型はこの差で定義する。

制約（SHACL）例
```turtle
gt:PalletSingleLocationShape a sh:NodeShape ;
  sh:targetClass gt:Pallet ;
  sh:property [ sh:path gt:currentZone ; sh:maxCount 1 ;
    sh:message "パレットは同一有効時刻に複数ゾーンに存在できない" ] .

gt:HazmatAdjacencyShape a sh:NodeShape ;
  sh:targetClass gt:Slot ;
  sh:sparql [ sh:message "危険物クラスの隣接禁止に違反" ;
    sh:select """SELECT $this WHERE {
      $this gt:holds ?a . $this gt:adjacentTo ?s . ?s gt:holds ?b .
      ?a gt:hazClass ?ca . ?b gt:hazClass ?cb . ?ca gt:incompatibleWith ?cb . }""" ] .

gt:ZoneCapacityShape a sh:NodeShape ;
  sh:targetClass gt:Zone ;
  sh:sparql [ sh:message "ゾーン容量超過" ;
    sh:select """SELECT $this WHERE {
      $this gt:capacity ?cap . { SELECT $this (COUNT(?o) AS ?n) WHERE { ?o gt:currentZone $this } GROUP BY $this }
      FILTER(?n > ?cap) }""" ] .
```
確率的事実に対する検査は、確信度 ≥ 0.7 の信念を対象に行い、違反の確信度は関与する信念の確信度の積で近似する。

### 5.4 接地層（C4–C7）

意味プローブ α
- 入力：型付きスロット（位置埋め込み、型ロジット、外観埋め込み）と時刻。
- ヘッド：存在（スロットが実在物体か）、型（オントロジークラス）、位置（ゾーン分類＋床面座標回帰）、状態（ディスポジション分類）、関係（集約：ケース→パレットの所属。ペアワイズ分類）。
- 出力：`gt:Belief` の集合（RDF-star）。確信度は温度スケーリングで較正し、ECE ≤ 0.05 を維持する。
- 学習：アンカー自己教師（アンカー時刻の真値との照合）、少量の人手ラベル、制約損失。

記号条件付け γ
- 入力：現在の信念KGから対象区画に関する部分グラフ（オーダー、作業割当、到着予定、ゾーン制約、直近の乖離）を抽出。
- 埋め込み：R-GCN系GNNで固定長ベクトル（次元256【要調整】）に変換。比較対象として、部分グラフをテキスト直列化して小型テキストエンコーダに通す方式も実装する。
- 注入：潜在動態モデルの条件トークンとして与える。静的文脈と動的文脈を分けて与え、H2のアブレーションを可能にする。

整合性検査（C6）と ε の計算
- 毎分、直近の z_t から h ∈ {10秒, 60秒, 5分, 30分} のロールアウトを行い、α で記号化した予測事実集合と、記録側の予定（F による遷移）から得た事実集合の距離 d を計算して ε_h として記録する。
- SHACL検証は α の出力（現在）と予測（将来）の両方に対して行い、将来違反は「予兆」としてダッシュボードに表示する。
- 制約損失：違反確率に対する罰則を微分可能推論（Scallop または LTN）で構成し、C2の学習に戻す。

同一性解決（C7）
- トラック（スロットの時間的連続）とオントロジー個体の対応付けを、位置予測と外観埋め込みの費用でハンガリアン割当により決定。
- 遮蔽中はWMの予測位置で個体を保持し、再出現時に割当を更新。RFID/バーコードのアンカーで強制的に再同定する。
- 評価：ID切替率、IDF1。

乖離台帳（C9）スキーマ

| 項目 | 内容 |
|---|---|
| discrepancy_id | 一意ID |
| object_id | 対象物体（オントロジー個体） |
| physical_belief | 値、確信度、出所、有効時刻 |
| record_claim | 値、出所システム、登録時刻 |
| discrepancy_type | unscanned_move / wrong_slot / wrong_scan / late_registration / ghost_stock / other |
| severity | low / medium / high（業務影響で定義：出荷差止め、誤出荷リスクなど） |
| detected_at, ε_at_detection | 検知時刻、検知時の ε |
| status, resolution, resolver | open / confirmed / resolved / dismissed、解決内容、解決者 |
| feedback_target | 訂正の反映先（WM再学習用ラベル／オントロジー修正／記録側への報告） |

優先ポリシー：安全に関わる判断（進入禁止、危険物隣接）は物理信念を優先、在庫・会計に関わる判断は記録を維持しつつ乖離を人が確認する。PoCでは自動反映は行わず、全件人が判定する。

### 5.5 データ空間層（C12）

- 交換単位：`gt:Belief`（接地済み主張）と予測（値、予測区間、ホライズン、モデル版）に PROV-O の出所を付与したもの。生映像・潜在表現は交換しない（H8で潜在共有の漏洩評価は別途実施）。
- ポリシー：ODRLで「目的限定（到着予定の共有は入荷計画のみに使用）」「保持期間」「再共有禁止」を記述し、EDCコネクタで強制。
- 互換性：ウラノス・エコシステムのデータ連携仕様との整合を確認する項目（識別子、契約交渉、監査ログ）をP2で評価する。

### 5.6 アプリケーション層（C10、C13）

WHAT-IFクエリ（文法は付録C）
```
PREDICT ?queue_len, ?cycle_time
AT +10min, +30min
WHERE station = gt:Station_S3
GIVEN do(gt:Conveyor_C1.speed := 1.2 * current)
SAMPLES 200
INTERVAL 0.9
```
コンパイル：`gt:Conveyor_C1` を対応する潜在スロットまたは行動変数に解決し、介入を行動系列の上書きとして与える。ロールアウト後、α で記号化し、KPIをKG上で集計して返す。

ダッシュボード
- 乖離一覧（型、重要度、対象、証跡映像へのリンク〈区画内端末でのみ再生〉）。
- ε の推移（ホライズン別、管理限界付き）と将来違反の予兆。
- WHAT-IFの実行と結果（予測区間付き）。
- 訂正UI：オペレータが乖離を確認・却下し、正しい値を入力。入力はフィードバックとしてWM再学習ラベルとオントロジー修正候補に配信される。

### 5.7 データ管理・プライバシー・セキュリティ

- 生映像はエッジ端末内に7日間保持し、区画外へ出さない。証跡再生は区画内端末に限定。
- 人物は匿名化した「作業者」個体として扱い、顔・体型は特徴量化前に不可逆処理。個人識別・勤怠評価には使用しない旨を運用規程に明記。
- 学習に用いる特徴量・アンカー・イベントは暗号化ストレージに保存。アクセスはロール別。
- モデル・データ・設定は版管理し、全評価はシードと設定ファイルから再現可能とする。

### 5.8 安全設計

- WMの計画出力は助言のみ。既存の安全インターロック（ライトカーテン、AGVの安全センサ）に介入しない。
- 危険予兆（人物在室中の車両進入予測）の表示は行うが、警報系の代替とはしない。
- 乖離注入実験は、業務側責任者の事前承認、実施時間帯の限定、対象物体の明示、終了後の原状回復を必須とする。

### 6.2 実験の詳細

EXP-01 アンカー接地の基礎精度
- 手順：P0でシミュレーション真値により α を学習し、真値との照合で上限性能を把握。P1で実サイトの2週間分のアンカー（想定：スキャン3,000件以上、RFID通過500件以上）を時系列で分割（前10日学習、後4日評価）。
- 条件：遮蔽率（0–20%, 20–50%, 50%以上）、照明（昼、夜間照明）、混雑度（作業者数）で層別。
- 出力：事実種別ごとのF1、混同行列、遮蔽率別の劣化曲線、較正曲線とECE。

EXP-02 遮蔽下の同一性維持
- 手順：棚裏通過、積み重ね、作業者による隠蔽の各シナリオをP0で200回生成し、P1では自然発生した遮蔽イベントを抽出して評価。
- 条件：WM予測位置を使う／使わない（単純トラッキング）の比較。
- 出力：ID切替率、IDF1、遮蔽時間別の維持率。

EXP-03 記号条件付けのアブレーション
- 手順：同一の評価期間に対し、(a) 条件なし、(b) 静的文脈、(c) 動的文脈の3条件で予測誤差を計測。γ の実装（GNN／テキスト直列化）も比較。
- 出力：ホライズン別誤差曲線、有効ホライズン H*、統計検定（対応ありの比較、ブートストラップ95%区間）。

EXP-04 整合性ギャップの計測とドリフト注入
- 手順：2週間の平常運転で ε_h の分布を推定し管理限界を設定。その後、業務側と合意した手順変更（検品位置変更、ピッキング順序変更）を各3日実施し、ε の応答を計測。変更前後の ε を用いてAUROCを算出。
- 出力：ε の時系列、管理限界、AUROC、ε 分解（(1)(2)(3）の寄与推定）。

EXP-05 乖離注入と検知
- 手順：乖離5型×10件以上を、時間帯と対象を無作為化して2週間に分散して注入。注入台帳は実験者のみが保持し、検知側には知らせない（盲検）。
- 出力：型別の検知率、誤報数／日、検知遅延分布、誤報の原因分類。
- 安全：注入は業務責任者の承認のもと、出荷に影響しない物体で実施し、実験終了時に原状回復。

EXP-06 シールド付き潜在計画
- 手順：P0の模擬AGVで、進入禁止ゾーン・危険物隣接・容量制約を含む100タスクを、シールド有／無で実行。
- 出力：違反件数、タスク完了時間、経路長。P1では助言表示のみとし、オペレータの採否を記録。

EXP-07 WHAT-IF反実仮想
- 手順：介入3種（コンベア速度、担当人数、一時置き場位置）について、事前に予測KPIと90%区間を記録。業務側と合意した介入を各2回実施し実測と比較。実施不可の介入はP0で較正したシミュレーションで代替。
- 出力：相対誤差、区間被覆率、介入ごとの予測–実測プロット。

EXP-08 概念発見
- 手順：新しい荷姿・工程・置き場運用を1種ずつ、オントロジー未登録のまま導入。2週間後に残差クラスタから候補を生成し、盲検の評価者が上位5候補を判定。
- 出力：出現率、候補の説明の妥当性（評価者3名の一致率）。

EXP-09 連合ツインと漏洩評価
- 手順：本サイトと模擬第二拠点の間で、到着予定と在庫状態の予測をEDC経由で交換。受領側で予測の較正（ECE）を評価。別途、潜在表現を共有した場合の漏洩を、復元デコーダ学習と人物再識別で評価。
- 出力：ECE、ODRLポリシー違反の監査ログ、復元画像の品質（SSIM/PSNR）、再識別精度。

EXP-10 オペレータ評価
- 手順：現場リーダー・作業者5名以上に、模擬例外10件を従来手順とダッシュボードの両方で処理してもらう（順序は無作為化）。
- 出力：解決時間、正答率、訂正反映率、SUS、自由記述。

EXP-11 非機能
- 手順：観測から信念KG更新までのE2E遅延を継続計測。稼働率、障害時の復旧時間、月額計算コストを記録。
- 出力：遅延分布（p50/p95）、稼働率、コスト試算（区画あたり）。

### 6.4 統計設計

- 比較は同一期間・同一入力に対する対応ありの比較とし、ブートストラップで95%信頼区間を示す。
- 検知率などの割合は Wilson区間で報告。50件の注入で検知率90%の下側95%区間は約79%となるため、可能なら注入を80件以上に増やす。
- 学習と評価の分割は時系列順（未来を評価）とし、同一日のデータが両方に入らないようにする。
- 全実験で乱数シードを3種以上用い、平均と分散を報告する。

### 6.5 評価基盤と再現性

- 指標計算はC14の共通スクリプトで行い、入力データの版、モデルの版、設定をMLflowに記録する。
- 各実験は「設定ファイル1つ」から再実行できる状態にし、成果物（表・図）は自動生成する。

- 知財：接地層の設計（α/γ、ε、アンカー自己教師、WHAT-IFコンパイル）は新規性の検討対象。第三者モデル・オントロジーのライセンス（各モデルの利用条件、EPCIS/AAS等の標準の利用条件）を一覧化する。
- 標準整合：EPCIS 2.0、AAS、OPC UA、ODRL、PROV-O に準拠し、独自拡張は名前空間を分けて管理する。

## 付録A 指標の定義

事実集合間の距離 d
- 対象時刻の事実集合 S_pred（予測）と S_ref（参照）について、事実種別 k（存在、型、位置、状態、関係）ごとに不一致率 m_k を計算し、業務重要度の重み w_k で加重平均する：d = Σ_k w_k · m_k。
- 位置事実の不一致は、ゾーン一致を0、隣接ゾーンを0.5、それ以外を1とする。
- 重み w_k はP0で業務側と合意して固定する（初期値：位置0.4、状態0.3、関係0.2、型0.1、存在は前提条件として別集計）。

整合性ギャップ
- ε_h = (1/N) Σ_t d( α(f^h(z_t)), F^h(α(z_t)) )。N は評価時刻数。アンカー時刻に限定した ε_h^anchor も併記。

接地精度
- 事実種別ごとの精度・再現率・F1。真値はアンカー時刻の確定事実（P1では棚卸し目視を追加）。
- ID切替率：単位時間・物体あたりのID切替回数。IDF1は多物体追跡の標準定義に従う。

予測誤差と有効ホライズン
- 潜在空間誤差：予測潜在と実潜在のコサイン距離の平均。
- 記号空間誤差：α で復号した事実集合の距離 d。
- 有効ホライズン H*：記号空間誤差が τ（初期値0.2）を超えない最大の h。

乖離検知
- 検知率 = 検知された注入乖離数／注入数（対象・型が正しい場合のみ検知とみなす）。
- 誤報 = 注入台帳に該当がなく、人の確認で乖離が存在しなかった台帳エントリ数（1日あたり）。
- 検知遅延 = 台帳生成時刻 − 注入時刻。

較正
- ECE（Expected Calibration Error）：確信度を10区間に分け、各区間の平均確信度と実際の正答率の差の加重平均。

漏洩評価
- 復元攻撃：共有潜在から画像を復元するデコーダを攻撃者が学習し、元画像とのSSIM/PSNRを評価。
- 再識別攻撃：共有潜在から匿名作業者個体を突合する分類器のTop-1精度をチャンス率と比較。

## 付録B オントロジー拡張の要点

- 名前空間 `gt:` はPoC限定とし、標準（EPCIS 2.0、AAS、SOSA/SSN、PROV-O、BFO/IOF）とのマッピングを別表で管理する。
- 信念はRDF-starで `<< :Pallet42 gt:currentZone :ZoneB >> gt:confidence 0.93 ; gt:source gt:WM ; gt:validFrom "..." ; gt:transactionTime "..."` の形で格納する。
- 継続体（`gt:Pallet`, `gt:Case`, `gt:Vehicle`, `gt:Worker`（匿名）, `gt:Zone`, `gt:Slot`, `gt:Equipment`）はオントロジー層に、生起体（移動、荷役、検品、待機）はWMが学習し、EPCISイベントとしてのみ記号化する。
- SHACL制約は「警告」「違反」の2段階で運用し、誤報率に応じて昇格する。

## 付録C WHAT-IFクエリ文法（BNF）

```
<query>     ::= "PREDICT" <vars> "AT" <horizons> ["WHERE" <filter>] ["GIVEN" <interventions>] [<options>]
<vars>      ::= <var> {"," <var>}
<horizons>  ::= <offset> {"," <offset>}          ; 例: +10min, +30min, +2h
<filter>    ::= <triple-pattern> {"AND" <triple-pattern>}
<interventions> ::= <do> {"," <do>}
<do>        ::= "do(" <entity> "." <property> ":=" <expr> ")"
             | "do(" <entity> "." <property> ":=" "absent" ")"
<options>   ::= ["SAMPLES" <int>] ["INTERVAL" <prob>] ["MODEL" <model-version>]
<expr>      ::= <number> | <number> "*" "current" | "current" ("+"|"-") <number>
```
意味：`<entity>` は信念KG上の個体。コンパイラは個体を潜在スロットまたは行動変数に解決し、`do` を行動系列の上書きとして与える。解決できない個体・属性はエラーとし、介入不能である旨と代替（シミュレーション）を返す。返り値は各 `<var>` の点推定と `INTERVAL` で指定した予測区間、使用モデル版、ロールアウト数。
