## 考察

機械的な数値としては `injected_concept_top5_hit=3 >= 2` で合格基準を満たしているが、smoke実行（`n_candidates=5`、複数の独立した候補が3種の注入概念をそれぞれ言い当てていた）とは異なり、**本実行では候補が1件のみで、その1件が3種すべてに「命中」している**。

`eval/scoring.score_concept_discovery()` の命中判定ロジックは、候補クラスタの各メンバー（スロット×フレーム）の観測時刻が、いずれかの注入イベントの `t_true` と `time_tolerance_s`（5秒）以内で近接しているかどうかで判定する（個体レベルの厳密対応付けはできないための時間的近接性の代理指標、実装コメント参照）。10エピソード規模では `min_cluster_size=3`（`full_run` で未変更）に対してクラスタリング（HDBSCAN）が収束し、既知シンボルで説明できない残差が1つの大きな塊としてまとまった可能性が高い。この1つの塊が広い時間範囲にまたがるメンバーを含んでいれば、3種の注入がそれぞれ別の時刻・別のエピソードで起きていても、時間的近接性だけを見る判定ロジックでは「3種とも命中」と数えられてしまう——これは「3つの異なる新概念を区別して発見した」ことの実証にはなっておらず、EXP-06（シールドが一度も試されなかった退行実験）と同種の「機械的合格が実質を伴わない」パターンである。

原因の切り分け（要フォローアップ）：
1. **クラスタリングパラメータが本実行スケールに合っていない**：`min_cluster_size`（=3）や既存シンボルによる説明済みクラスタのフィルタ閾値が、smoke（2エピソード）向けにチューニングされたまま `full_run` で変更されていない。10エピソード相当のより豊富な残差データに対しては、より細かい粒度でクラスタが分離されるようパラメータを調整する必要がある可能性が高い。
2. **命中判定ロジック自体の粗さ**：時間的近接性だけで判定する現在の代理指標は、候補が広範囲をカバーする「キャッチオール」クラスタであるほど見かけ上の命中率が上がるという構造的な弱点を持つ。候補ごとに「メンバーの時間分布がどれだけ集中しているか」も合わせて報告する（例：命中したがクラスタが広範囲に散らばっている場合はフラグを立てる）ような指標の改善が必要。

なお、H7 のもう一つの評価軸である「盲検の評価者3名による候補説明の妥当性判定」（poc_plan.md 6.2）は、本関数では測定できず人手評価が必要（`docs/results/EXP-08_protocol.md` は未作成——EXP-10 と同様の準備が必要、次のアクション参照）。

## 次のアクション（優先順）
1. `full_run` の `min_cluster_size`／クラスタ分離パラメータを10エピソード規模に合わせて再チューニングし、複数の独立した候補が生成されるか確認した上で再実行する。
2. `score_concept_discovery()` に「候補クラスタの時間的凝集度」を追加指標として実装し、キャッチオールクラスタによる見かけ上の命中を区別できるようにする。
3. H7 の人手評価部分（盲検評価者3名による候補説明の一致率）の手順書を、EXP-10 の `docs/results/EXP-10_protocol.md` と同じ形式で作成する。
