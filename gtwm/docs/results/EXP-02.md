# EXP-02 結果

## 目的
遮蔽下でもWM予測位置を使うことで個体の同一性を維持できるかを検証する（H1、poc_plan.md 3.1）。

## 設定
- config: `experiments/EXP-02/config.yaml`（`full_run`：`p0_eval` 全10エピソードをプールして集計するよう `measure()` を修正——smoke〜Phase B Stage 1時点は単一エピソードのみを処理する既知の制約があったが、本実行にあわせて複数エピソード集計に対応させた）
- データ: `p0_eval`（5分×10本）、WMの予測位置あり／なし（単純トラッキング）の比較
- WM チェックポイント: `runs/wm/checkpoints_full/best.pt`
- 実行: `runs/EXP-02/20260913-152707/`
- seeds: [0, 1, 2]
- 所要時間: 544.30s

## 判定
**不合格**

## 考察

WM予測位置を使うことで単純トラッキングと比べて ID 切替率は約58%削減されている（0.394 → 0.166）——手法自体は方向として機能しているが、目標値（0.05）の3倍以上残っている。

一方で `idf1`（0.794 vs baseline 0.790）はほぼ差が無い。ID切替率と IDF1 が食い違う方向を示しているのは一見矛盾に見えるが、IDF1 は「正しい ID を持つ検出の割合」という別側面の指標であり、散発的な切替が起きても大半のフレームで正しい対応付けが保たれていれば IDF1 は高く出ることと整合する（=同一性が壊れる場面は限定的だが、壊れた際の切替そのものが目標より頻発している）。

原因仮説（優先度順）：
1. **同一性解決の距離ゲート・遮蔽保持ロジックが密集シーンに対して粗い**：`grounding/identity.py` のハンガリアン割当は WM予測位置と外見埋め込みの距離を使うが、`appearance_weight=0.0` で運用されている箇所がある（session 05 の実装メモ参照）ため、位置が近接する複数個体（例：同じラック前で作業する複数パレット）を外見情報なしに区別できず、切替が起きやすい可能性がある。
2. **α のゾーン分類精度が0.808（H1目標0.90未達、EXP-01参照）であることが間接的に影響**：スロットの型・位置推定が不安定なタイミングでは、そもそも「どの検出がどのスロットに対応するか」の判断が揺らぎやすい。
3. **`p0_eval` のシナリオ多様性**：単純トラッキングに対する改善幅（58%減）自体は smoke データでの傾向と整合しており、手法として無効ではない——目標値0.05自体が「遮蔽率の高い密集シナリオ」を想定した厳しい基準である可能性があり、遮蔽率別に層別した分析が必要。

## 次のアクション（優先順）
1. 外見埋め込み（`appearance_weight`）を実際の値で使うよう `identity.py` の呼び出し側を見直し、位置のみに頼らない同一性解決に改善できるか検証する。
2. 遮蔽率（0–20%/20–50%/50%以上）で層別した ID 切替率を算出し、どの遮蔽帯で目標未達が集中しているかを特定する（EXP-01の考察と同じ切り口）。
3. EXP-01（α の位置精度）の改善が本指標にも波及するかを、EXP-01改善後に再検証する。
