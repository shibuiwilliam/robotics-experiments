# EXP-01 アンカー接地の基礎精度

出典：`docs/poc_plan.md` 6.1・6.2（本ファイルは転記であり要約ではない。数値は
`experiments/criteria.yaml` の H1 と一致させること）。

## 検証仮説

H1（3.1）：潜在状態から業務事実を高精度に復号できる。

## 段階

P0→P1（3週）。

## 手順（6.2 転記）

P0でシミュレーション真値により α を学習し、真値との照合で上限性能を把握する。
P1で実サイトの2週間分のアンカー（想定：スキャン3,000件以上、RFID通過500件以上）を
時系列で分割（前10日学習、後4日評価）。

## 条件（6.2 転記）

遮蔽率（0–20%, 20–50%, 50%以上）、照明（昼、夜間照明）、混雑度（作業者数）で層別。

## 出力（6.2 転記）

事実種別ごとのF1、混同行列、遮蔽率別の劣化曲線、較正曲線とECE。

## 合格基準（H1、3.1 転記。`experiments/criteria.yaml` が正）

- 位置事実F1（アンカー時刻） ≥ 0.90
- 型分類精度 ≥ 0.95
- （ID切替率 ≤ 0.05回/物体・時間 は EXP-02 で測定する。3.1の同一仮説の指標だが、
  6.1でEXP-01=「アンカー接地の基礎精度」、EXP-02=「遮蔽下の同一性維持」と分担が
  明記されているため、本実験ではID切替率は対象外とする）

## 未達の場合の判断（3.2 転記）

F1 ≥ 0.80 なら改善余地ありとして継続、0.80未満ならセンサ配置・エンコーダ選定を
再検討しP1を1か月延長。

## Smoke モード

`configs/grounding/probe_train_smoke.yaml` を使い、`data/sim/smoke` の1エピソード
（30秒）でP0の上限性能測定パイプラインを実行する。**smoke は参考値であり、
合否判定には使わない**。本実行には P0の `p0_train`/`p0_eval`（5分×複数本、
poc_plan.md 6.3 データ収集計画を参照）相当のデータ生成が必要（所要時間は
`gtwm sim gen` の実測値から見積もる）。
