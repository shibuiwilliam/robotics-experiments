# EXP-09 連合ツインと漏洩評価

- 仮説：H8「拠点間で予測を安全に交換できる」
- 段階：P2
- 所要（計画）：4週

## 手順（poc_plan.md 6.2 原文）

> 本サイトと模擬第二拠点の間で、到着予定と在庫状態の予測をEDC経由で交換。受領側で予測の較正
> （ECE）を評価。別途、潜在表現を共有した場合の漏洩を、復元デコーダ学習と人物再識別で評価。

## 条件（poc_plan.md 3.2 H8）

- 構成：本サイトと模擬第二拠点（P0のシミュレーション環境を「別組織」として運用）。共有語彙
  （EPCIS 2.0 + PoC拡張）で予測（到着予定、在庫状態）を交換。
- 漏洩評価：共有する潜在表現に対して、復元攻撃（潜在→画像のデコーダ学習）と人物再識別攻撃を
  実施。

## 出力（poc_plan.md 6.2 原文）

> ECE、ODRLポリシー違反の監査ログ、復元画像の品質（SSIM/PSNR）、再識別精度。

## 合格基準（`experiments/criteria.yaml` H8）

| 指標 | 目標 |
|---|---|
| ece | ≤ 0.05 |
| reconstruction_ssim | ≤ 0.30 |
| reid_top1_vs_chance | ≤ 1.2倍 |

## このセッションでの簡略化（ADR-0002 参照）

- **EDC ではなく最小 HTTP コネクタ**：Eclipse Dataspace Components の統合は Java 環境・
  Postgres 等の追加が必要で1日を超えるため、ADR-0002 により Python 標準ライブラリのみの
  最小 HTTP コネクタ（ODRL相当のポリシー検査＋監査ログ）を実装した。実際に Docker 越しの
  HTTP 到達性・healthcheck・ポリシー拒否は `make up-p2` で手動確認済み。このスモーク測定
  自体は `dataspace.connector.Connector` を in-process で使う（Docker 非依存）。
- **模擬第二拠点**：同じ倉庫レイアウトを別 seed で生成したデータセット（レイアウトを変える
  必要はないと docs/prompts.md セッション10自身が明記）。
- **受領側 ECE の簡略化**：`PredictionRecord` は値・区間・ホライズン・モデル版のみを運び
  確信度を運ばない（poc_plan.md 5.5 の交換単位定義通り）。そのため本 smoke では全予測を
  一様確信度1.0として送った体で ECE（＝誤り率）を計算する。本実行では確信度を伴う交換
  スキーマへの拡張が必要（`docs/status.md` に申し送り）。
- **ポリシー違反の生成**：本来は乖離台帳と同様、実運用中に自然発生する誤った目的宣言を扱うが、
  smoke では意図的に1件、許可されていない目的（"marketing"）での要求を発行し、拒否・監査
  ログ記録を確認する。

## 判定

smoke 実行の判定は常に「参考（smoke）」。本実行の判定には `full_run` セクションに記載の
本番相当データ量・Docker越しコネクタでの実行が必要。
