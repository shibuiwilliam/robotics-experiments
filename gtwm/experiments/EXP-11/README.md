# EXP-11 非機能（遅延、可用性、コスト）

- 仮説: N1（非機能要件を満たす）
- 段階: P1–P2
- 所要（計画目安）: 継続

## 手順（poc_plan.md 6.2 原文）

観測から信念KG更新までのE2E遅延を継続計測。稼働率、障害時の復旧時間、月額計算コストを
記録。

## 出力（poc_plan.md 6.2 原文）

遅延分布（p50/p95）、稼働率、コスト試算（区画あたり）。

## 合格基準（poc_plan.md 3.1、`experiments/criteria.yaml` N1）

| 指標 | 目標値 |
|---|---|
| e2e_latency_s | <= 1.0秒（観測→信念KG更新） |
| availability | >= 0.99（稼働率、営業時間） |
| monthly_cost_per_zone | 試算提示のみ（閾値なし） |

## smoke での簡略化（`src/gtwm/eval/experiments/exp11.py` 参照）

- E2E遅延：`grounding/ground_run.run_ground` の各サンプルフレームについて
  「フレーム読込開始 → 信念KGコミット完了」の経過時間を計測。現在の実装は
  バッチ処理（全フレーム処理後に1回だけコミット）なので、値はストリーミング実装より
  悲観的な上限になる。
- 稼働率：長期間デプロイされたサービスが無いと本来のSLA計測はできない
  （本 PoC は全フェーズをシミュレーションで行うため対象外）。代わりに
  `n_trials` 回パイプラインを実行し、例外なく完走した割合を代理指標として報告する。
- コスト試算：実測した生成速度（session02/08）から按分したナラティブな概算。

## 本実行に必要なデータ・時間

継続計測（デプロイ後、観測→信念KG更新の実時間ログを収集）。稼働率は最低でも
1営業日以上の連続稼働実績が必要。
