# EXP-03 記号条件付けのアブレーション

出典：`docs/poc_plan.md` 6.1・6.2（転記。数値は `experiments/criteria.yaml` の H2 と一致）。

## 検証仮説

H2（3.1）：記号条件付けはWMの予測を改善する。

## 段階

P0→P1（3週）。

## 手順（6.2 転記）

同一の評価期間に対し、(a) 条件なし、(b) 静的文脈、(c) 動的文脈の3条件で予測誤差を
計測する。γ の実装（GNN／テキスト直列化）も比較する。

## 出力（6.2 転記）

ホライズン別誤差曲線、有効ホライズン H*、統計検定（対応ありの比較、ブートストラップ
95%区間）。

## 合格基準（H2、3.1 転記）

- 60秒先誤差 20%以上改善（無条件比）
- 有効ホライズン H* が1.5倍以上（無条件比）

## Smoke モード

`data/sim/wm_smoke`（session04が生成した2episode、各30秒）で、潜在空間誤差
（予測潜在と実潜在のコサイン距離）を (a) 条件なし、(b) 静的文脈（ゾーン隣接の
固定グラフ）、(c) 動的文脈（各時刻の実ゾーン占有）の3条件で比較する。

**このセッション（06）の簡略化**（`eval/experiments/exp03.py` の docstring 参照）：
- 記号空間誤差（α復号後のd）ではなく潜在空間誤差（コサイン距離）で比較する
  （smoke規模のエンコーダ精度では記号復号自体のノイズが条件付け効果を隠すため）。
- 「動的文脈」はオーダー・作業割当・到着予定（EPCIS記録）そのものではなく、
  各時刻の実ゾーン占有を代理として使う。
- 30秒のsmokeエピソードでは60秒先の比較ができない（エピソード長より長いホライズン
  は原理的に測れない）。smoke では 1〜8秒先までの誤差を報告し、
  `error_improvement_60s` はそのうち最も60秒に近いホライズン（8秒）での値である
  ことを `closest_horizon_to_60s` フィールドで明示する。

**smoke は参考値であり、合否判定には使わない**。本実行には30秒を大幅に超える
（60秒以上先を評価できる）エピソード生成が必要。
