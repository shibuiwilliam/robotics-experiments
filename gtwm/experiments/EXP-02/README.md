# EXP-02 遮蔽下の同一性維持

出典：`docs/poc_plan.md` 6.1・6.2（転記。数値は `experiments/criteria.yaml` の H1 と一致）。

## 検証仮説

H1（3.1）：潜在状態から業務事実を高精度に復号できる（の一部：ID切替率）。

## 段階

P0→P1（2週）。

## 手順（6.2 転記）

棚裏通過、積み重ね、作業者による隠蔽の各シナリオをP0で200回生成し、P1では
自然発生した遮蔽イベントを抽出して評価する。

## 条件（6.2 転記）

WM予測位置を使う／使わない（単純トラッキング）の比較。

## 出力（6.2 転記）

ID切替率、IDF1、遮蔽時間別の維持率。

## 合格基準（H1、3.1 転記）

- ID切替率 ≤ 0.05回/物体・時間

## Smoke モード

`data/sim/smoke` の1エピソード（30秒、62個体）で、`grounding/identity.py`
（ハンガリアン割当・遮蔽保持・強制再同定）を通しで走らせ、「予測なし（単純
保持）」と「予測あり（等速外挿）」の2条件でID切替率・IDF1を比較する。

**このセッション（06）の簡略化**：「予測あり」条件は `wm.dynamics.Dynamics`
本物のロールアウトではなく、既知速度の等速外挿を使う（`eval/experiments/exp02.py`
の docstring 参照）。本物のロールアウトには遮蔽開始時点の対象個体がどのスロットに
対応するかを毎フレームの視覚パイプラインで特定する必要があり、smoke規模を超える
ため本実行時に置き換える。

**副産物**：本実験の実装中に `grounding/identity.py` の `update_occluded_entities`
が、マッチした個体の位置を観測値で更新していなかったバグ（`ground_run.py` が
毎フレーム真値からエンティティを作り直すため単体テスト以外で一度も検出されて
いなかった）を発見・修正した（`slot_positions` 引数を追加）。

**smoke は参考値であり、合否判定には使わない**。本実行にはP0の200回相当の
遮蔽シナリオ生成（棚裏通過・積み重ね・作業者隠蔽）が必要。

**smoke結果の解釈上の注意**：`data/sim/smoke` の30秒エピソードでは、パレット・
ケースの大半が静止しており、遮蔽が起きても再出現時の真の位置が変わらないため、
「予測あり」と「予測なし（単純保持）」の両条件でID切替率・IDF1が同一の値になる
（実測：両条件とも id_switch_rate=0）。占有スロットに動きが無ければ、外挿しても
保持しても同じ位置に戻るため、これは実装の誤りではなく smoke データの性質である。
2条件の差が意味を持つのは、遮蔽中に対象が実際に移動する状況（AGV・作業者の遮蔽、
本実行の200回シナリオ）に限られる。
