# EXP-07 WHAT-IF反実仮想

出典：`docs/poc_plan.md` 6.1・6.2・3.2（本ファイルは転記であり要約ではない。数値は
`experiments/criteria.yaml` の H6 と一致させること）。

## 検証仮説

H6（3.1）：WHAT-IFの反実仮想予測は実測と整合する。

## 段階

P2（6週）。

## 対象（3.2 転記）

介入例：コンベア速度の変更、ピッキング担当の人数変更、一時置き場の位置変更。

## 手順（6.2 転記）

介入3種（コンベア速度、担当人数、一時置き場位置）について、事前に予測KPI（待ち行列長、
処理時間、動線長）と90%区間を記録。業務側と合意した介入を各2回実施し実測と比較。
実施不可の介入はP0で較正したシミュレーションで代替。

## 出力（6.2 転記）

相対誤差、区間被覆率、介入ごとの予測–実測プロット。

## 合格基準（H6、3.1 転記。`experiments/criteria.yaml` が正）

- KPI相対誤差 ≤ 15%
- 90%予測区間の被覆率 ≥ 80%

## 未達の場合の判断

poc_plan.md 3.2 に H6 専用の延長基準は明記されていない（3.3「総合判定」の一般規則：
未達は原因分析と改善案を添えて1か月延長を1回まで、2回目の未達で「不成立」として記録）。

## Smoke モードでの簡略化（docs/status.md にも記載）

- この sim は作業者の移動とパレット/ケースの実位置が独立している（`sim/drift.py` の
  スコープ限定と同根）。3介入を文字通り物理接続する手段が無いため、
  `sim/env.py`（`WarehouseEnv` の `active_workers`/`worker_speed_multiplier`/
  `worker_loop_overrides`）を使った代理を実装する：
  - コンベア速度変更 → 全作業者の巡回速度を一律倍にする。
  - 担当人数変更 → 指定した作業者をスプライン起点で静止させる。
  - 一時置き場位置変更 → 指定した作業者の巡回経路を差し替える。
  これらは記録レベルの書き換え（`sim/drift.py` 方式）ではなく、実際に
  `gtwm sim gen` で物理的に異なる軌跡を持つエピソードとして生成される点で、
  よりシミュレーションとして誠実である（詳細は `eval/experiments/exp07.py` の
  モジュール docstring）。
- KPIは `queue_len`（対象ゾーンの作業者滞在数、時間窓平均）。パレット/ケースは
  この sim の制約でほぼ静的なため、作業者に限定しないと介入と無関係な定数項に
  信号が埋もれることを実測で確認した。
- `do()` の介入は `kg/whatif/compiler.py` の既存の簡略化（行動ベクトル次元0への
  一様上書き）をそのまま使う。介入の意味的正しさ（コンベア速度と行動値の対応の
  厳密さ）は保証しない。
- **smoke は参考値であり、合否判定には使わない**。本実行には実サイトでの介入実施
  （各2回）、300秒級のエピソード測定、行動空間の意味付け改善が必要
  （config.yaml の full_run 節参照）。
