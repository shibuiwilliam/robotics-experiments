# EXP-04 整合性ギャップの計測とドリフト注入

- 仮説: H3（整合性ギャップ ε はプロセス逸脱の検知指標として機能する）
- 段階: P1
- 所要（計画目安）: 4週

## 手順（poc_plan.md 6.2 原文）

2週間の平常運転で ε_h の分布を推定し管理限界を設定。その後、業務側と合意した手順変更
（検品位置変更、ピッキング順序変更）を各3日実施し、ε の応答を計測。変更前後の ε を
用いてAUROCを算出。

## 出力（poc_plan.md 6.2 原文）

ε の時系列、管理限界、AUROC、ε 分解（(1)知覚誤り (2)プロセス不遵守 (3)オントロジー
欠落の寄与推定）。

## 合格基準（poc_plan.md 3.1、`experiments/criteria.yaml` H3）

| 指標 | 目標値 |
|---|---|
| drift_detection_auroc | >= 0.85 |
| epsilon_daily_cv | <= 0.2（変動係数） |

## smoke での簡略化（`src/gtwm/eval/experiments/exp04.py` 参照）

- 2週間の平常運転 → `n_baseline_episodes` 本（既定3）の30秒エピソード。
- 3日間の手順変更 → `n_drift_episodes` 本（既定3）の、検品位置変更＋ピッキング順序変更を
  同時に有効化した30秒エピソード（`sim/drift.py`）。
- ε は h10s（10秒先）のみ評価する。h60s 以上は30秒エピソードでは1サンプルも
  得られない（本実行では duration を60秒超にする必要がある）。
- epsilon_daily_cv は「エピソード間の平均ε_10sの変動係数」で代替する。

## 本実行に必要なデータ・時間

2週間分の平常運転ログ（p1_train 相当を継続収集）+ 3日間ぶんの手順変更後ログ。
`gtwm sim gen` の実測生成速度（session02: 30秒エピソード約7秒、session08: 5分
エピソードは実測 約75秒/本）から按分すると、17日分（約2450分）のシミュレーション
生成だけで概算 6時間程度。
