# ADR-0031: 再接地の実行は「最初から再生して比べる」ジョブにする（M9-01）

- 日付: 2026-11-08
- 状態: 採択
- 触る層: reasoning（`regrounding_run`）、scripts（`reground`）

## 文脈

`sbp.knowledge.regrounding` は計画と差分レポートだけを持ち、実行（`run(plan)`）が無かった（所見 110）。G7 の統合テストは
「プローブ版ごとの確率」をテストが直接アサーションに書いていたが、運用の信念は **bridge-worker が昇格したイベントを belief-worker が
フィルタに通した事後**であり、プローブの出力そのものではない。実データの再接地は、その連鎖を新しい版で作り直す操作になる。

## 決定

1. **実行は運用の部品で最初から再生する。** 潜在 → プローブ（`ProbeSet`）→ `lift_events` → `BeliefIngest`（業務の主張を時刻順に混ぜる）。
   `sbp.reasoning.regrounding_run.reground` が計画の範囲を再生して比べる。`knowledge` は `bridge` / `reasoning` を import できないので、
   実行は `reasoning` に置く。
2. **既定は dry-run。** `--apply` のときだけ書く。書くのは「新文を足す → 旧文の `tx_to` を閉じる」の順（中断しても信念が消えない。重複は再実行で直る）。
3. **ライブに近い区切りで再生する。** bridge-worker は `batch_size` ずつ昇格する。再生も先頭から `batch_size` ずつ昇格するが、ライブの区切りは起動時刻・再起動・ウォーターマークの復元で変わるので、**一致は保証できない**（境目の変化点が食い違いうる）。差分は版の違いと区切りの違いを含む近似で、人がレポートを読んで判断する。
4. **フィルタの状態を持ち越すため、実体の最初の潜在から再生し、書くのは計画の期間だけ。**
5. **突き合わせは `(述語, valid_from)` の一致。** 一致して確信度が同じ（1e-9）なら触らない（再実行は何も変えない）。再生にあって旧文に無いものは「新規」、
   旧文にあって再生に無いものは「消滅」。比べる旧文は belief-worker が観測・主張から書いた文（来歴が `<prefix>/…`）だけ。人の訂正、結合の文（`/coupling/`）、
   似た名前の来歴は閉じない。
6. `regrounding_duration`（秒）をジョブが `metrics` に書く。

## 結果

- 全点が揃った単純な系列（単一バッチ、結合なし）では、同じプローブで再生すると差分が 0 件になる（単体テスト）。ライブの区切りが違う運用では 0 件にならない（上の 3）。
- 計画の事前（`GraphPlans`）はスクリプトがライブと同じく差す。複数フルーエントが同時刻に切り替わっても、それぞれ置き換える（レビュー指摘の再現テスト）。
- `as_of` で旧信念が、新しい `tx` で新信念が引ける（実 Oxigraph / Postgres / S3 / Redpanda の統合テスト）。

## 限界

- 主張は事象ログの業務トピックを最初から読む。保持期間を過ぎた期間は主張なしで再生され、差分に出る。
- 潜在は実体の最初から計画の終端（右開）までをページで読み、1 実体 100 万点まで（超えたら `--end` を前にする）。全実体の系列をメモリに持つ。
- **belief-worker が動いている最中の `--apply` は避ける。** 読み取りと閉じる処理の間にライブが書いた文は「消滅」として閉じられうる。スクリプトは終端が未来に及ぶ `--apply` を拒否する。
  並行する 2 つの `reground` を防ぐ仕組みは無い（二重に足される。再実行で重複は閉じる）。結合の文・寄与の記録（`ContributionRecord`）は再生しないので、新文の説明は「寄与が記録されていない」になる。
- 主張は idle（既定 3 秒）の無音で読み切ったとみなす。ブローカーが遅いと取りこぼし、「消滅」が増える。
- 新文の来歴は `<belief-worker の来歴>/regrounding/<plan_id>` で、元のイベント ID を持たない（再生したイベントはログに流さない）。
  説明は計画（理由・版）から辿る。
- 信念の結合（loopy BP、`_couple`）と照合（不一致の再起票）は再生しない。信念の事後だけを差し替える。差し替えた後の不一致は reconcile-worker が
  次の周期で拾う。新規・消滅した不一致のレポート欄は空のまま（M9 以降）。
- WM 版の昇格で潜在の次元が変わる場合は、新しい次元の表への移行が先（`make encode`）。
