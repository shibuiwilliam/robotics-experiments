# ADR-0025: ゲート G8 は「外界だけを模擬し、基盤の内側は運用コードで通した連鎖」が緑であること

- 日付: 2026-11-08
- 状態: 採択
- 触る層: テスト（`tests/integration/test_g8_workers.py`）。HITL H-22 の決定（案 A）の具体化

## 文脈

G8 の字面は「4 ワーカーを実物のサービス上で回し、各 `step()` が非ゼロを返す」だった。入力をテストが直接置いてよい
なら、各ワーカーは単独で動く（G5 の「完走させたのはテストコード」の繰り返し。所見 89）。H-22 で人が
**案 A（外界だけを模擬し、内側は運用コードで通す）**を選んだ。M8-24（推定パスの先頭）と M8-23（プローブ束の投入）は
そのための前提だった。

## 決定

1. **模擬してよいのは外界の 3 つだけ**: 物理の観測窓（`SynthWorld` → スプール JSONL）、業務システム（SQLite の
   モックと台本）、人の操作（API コマンド）。真値（オラクル）は業務の台本を作るためにテストが使い、基盤のコードには渡らない。
2. **連鎖は次の順で、すべて運用のコード（`build_worker` / `scripts/*`）で通す**:
   `train_koopman` → `encode`（潜在索引）→ ingest-worker（台帳・記録・主張イベント）→ `train_probe`（弱ラベル → ゲート →
   置き場）→ bridge-worker → belief-worker → reconcile-worker → （人のコマンド `resolve_discrepancy`）→
   learning-worker → scheduler-worker。
3. **G8 の条件**: (a) G0〜G7 の統合テストが緑のまま、(b) `test_g8_workers.py` が緑（上の連鎖で各 `step()` が非ゼロ）、
   (c) コードに `TODO(question)` が 0 件。
4. **ワーカーの数え方**: 元の「4 ワーカー」は bridge / belief / reconcile / scheduler。連鎖の入口と出口である
   ingest / learning も同じテストで通すので、6 ワーカーと 2 ジョブが非ゼロであることを確かめる。
5. **履歴の再生という条件を明記する**: テストは 8 時間ぶんの履歴を一度に流す。信念更新は流したイベントが増えるほど
   1.0 に飽和し、スケジューラの観測効用は 0 になる（確信している対象を観測し直す価値が無いのは正しい挙動）。
   スケジューラの検証では信念更新を 1 ステップ 1 件に絞り、迷っている信念で動かす。

## G8 が見つけたもの

連鎖を通した最初の日に、各ワーカーの単体・統合テストが緑のまま存在していた**連鎖の切れ目**が 6 つ見つかった
（ADR-0026、PROGRESS 所見 133）。外界だけを模擬する意味は、こうした「段の間の契約」を実際に走らせることにある。

## 結果

- M8 の字面のゲートが、運用で動くことを意味するようになった。
- 限界: 履歴の再生は実時間の運用と違う（イベントの到着順が決まらない）。到着順に依存する箇所は ADR-0026 で
  到着順に依存しない形にした。実データでの検証は別リポジトリ（ADR-0001）。
