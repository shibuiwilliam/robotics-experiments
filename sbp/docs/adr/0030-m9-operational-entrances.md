# ADR-0030: M9「運用の入口」を起こす（H-24 案 A）

- 日付: 2026-11-08
- 状態: 採択（人の判断: H-24 案 A、2026-11-08）
- 触る層: スコープ（docs/TASK.md の里程の追加）

## 文脈

M8 は 4 ワーカーを実物のサービス上で動かすことが目的で、G8 を通過した。しかし、ライブラリと統合テストはあるが**運用で呼ぶ者がいない**機能が残る
（H-24、PROGRESS 所見 103 / 110）: 再接地の実行（`run(plan)` が無い。版昇格 OPS-06 の必須手順）、予測・What-if・説明の入口、
未配線の指標 5 つ、LLM を使う機能の入口、SHACL 隔離・同一性束縛・空間束縛の運用経路。

## 決定

M9「運用の入口」を起こす。M8 の目的（ワーカーを動かす）と G8 の定義は変えない。優先順は依存の向きで決める。

| タスク | 内容 | 閉じる指標・条件 |
|---|---|---|
| M9-01 | 再接地の実行（`reground` ジョブ）。既定は dry-run、`--apply` で旧文の `tx_to` を閉じ新文を追加。差分レポートを markdown で保存 | `regrounding_duration` |
| M9-02 | 予測の周期ジョブ（WM のロールアウトから `predicted` の予測を作り、後から来る観測で採点） | `forecast_coverage` / `forecast_crps` |
| M9-03 | 問い合わせの入口（GraphQL: 予測・説明の読み出し。What-if はコマンド） | 設計書 §10.2 |
| M9-04 | G9: M9-01〜03 を外界だけの模擬で通す統合テスト、指標の分類（`test_metrics_wiring`）を更新 | G9 |

**M9 に入れない（人の判断が要るまま H-27 に移す）**: 同一性束縛の運用（`identity_bind_rate` / `identity_revoke_rate`。Track の入力となる知覚の
契約が本リポジトリに無く、束縛は現場のエッジの出力に依る）、LLM を使う機能の入口（概念提案・文書抽出・NL→クエリ・説明の文章化。どれを先に
入れるか、費用と来歴の方針が要る）、SHACL 隔離の運用経路（書く者が決まっていない）。

## 結果

- G9: G8 維持 + M9-04 緑。完了の定義は M8 と同じ（型・テスト・`make check` 緑・ADR / CHANGELOG・独立レビュー）。
- 指標の配線済みは 20 → 23（`regrounding_duration`、`forecast_coverage`、`forecast_crps`）。残り 2（identity 系）は H-27。

## 限界

- M9-01 の再接地は、プローブ版の昇格に伴う**信念の再計算**（潜在 → 昇格イベント → 信念更新の再生）を対象にする。WM 版の昇格（潜在の再計算）は
  エンコードジョブ（ADR-0023）で潜在を作り直してから同じジョブを走らせる。オントロジー MAJOR の再接地計画は別途。
