# ADR-0027: 同じ情報源の繰り返しの主張は置き換える（H-26）

- 日付: 2026-11-08
- 状態: 採択
- 触る層: reasoning（belief・ingest）

## 文脈

G8（ADR-0025）で履歴を一度に流すと、信念が 1.0 に飽和した（H-26）。疑いは 2 つあった。(a) 実体内で時刻が戻ったイベントの読み飛ばし、
(b) 同じ情報源の繰り返しの主張を独立な証拠として足すこと。

再現テスト（`tests/unit/reasoning/test_claim_saturation.py`）で **(b) が原因**と確かめた。業務システムは同じ状態を周期ごとに記録する。
主張は時間を進めず（遷移を適用せず）直前の事後に対数オッズを足すので、300 件の「稼働」で信念は 1 − 10⁻⁹ に張り付き、
後から来た「停止」の主張が十数件あっても戻らない。観測（昇格イベント）は状態の変わり目にしか無く、主張の数十分の一なので埋もれる。
**(a) は起きていない**: 実チェーン（G8 の履歴再生）で `OUT_OF_ORDER` は 0 件。

## 決定

1. **同じ情報源（`RecordEvidence.source`）の主張は、直前のものを置き換える。** 実体×フルーエントごとに、情報源別に「いま信念に含まれている
   主張の対数オッズ」を持ち、新しい主張を足す前に直前の分を引く（`update_belief(superseded_claim_log_odds=…)`）。
   業務記録は同じ状態を繰り返し言い、誤りも繰り返される——条件付き独立ではないので、件数は証拠にならない。
2. **持ち分は観測が入っても残す。** 空にすると、観測と主張が交互に来る運用で主張が再び積み上がる（独立レビュー）。
   事後は対数オッズの和なので、観測の後でも直前の主張の分を引いて新しい主張を足せる。
3. **別の情報源は別の証拠**として数える（情報源ごとに 1 件）。情報源が無い主張は 1 つの無名の情報源として扱う。
3b. **同じ情報源のより古い主張（`tx_time` が持ち分の時刻より前）は読み飛ばす**（`SkipReason.STALE_CLAIM`）。遅れて届いた古い主張が最新を上書きしない。
4. 書き込み失敗の取り消し（`undo`）は主張の持ち分も戻す。
5. **(a) は変えない**: 時刻が戻った観測は読み飛ばし、`SkipReason.OUT_OF_ORDER` で数える。発生を観測してから窓での並べ替えを決める（H-26 の案 1）。

## 結果

- 主張が何件続いても、事後は 1 件の主張の場合と同じ。末尾の主張が反対を言えば、件数に関係なく戻る。
- G8 の履歴再生の段（同じ consumer group で残りを全件）で `OUT_OF_ORDER` 0 件、末尾の状態に着地することを確認する。
- 移行: 保存済みの信念は変わらない（フィルタの状態だけが変わる）。再起動後は持ち分が空で、最初の主張が 1 件分足される。

## 限界

- 置き換えは「直前の主張の分を丸ごと引く」近似である。間に観測の遷移（滞在時間による減衰）が挟まると、信念に残っている分と引く分がずれる。
  また事後が対数オッズのクランプ（±20）に当たっていると、引く前の値が実際の和より小さく、反対の主張への置き換えで下がり過ぎる。実害は小さいが厳密ではない。
- 情報源は `RecordEvidence.source` の最初の 1 件で、粒度は取込の設定に依る（記録 ID の粒度にすると置き換えは効かない。現状は情報源のシステム IRI）。
- 同じ情報源が本当に独立な再測定をしても 1 件分しか数えない（保守側）。再測定の独立性を信頼性モデルに持たせるのは未決。
- G8 の台本は末尾が停止区間で、修正前でも再生の段は通る（実測）。飽和の弁別は単体テストが担い、統合は `OUT_OF_ORDER` 0 件と末尾の側への着地を確かめる。
- 設計書 §8.1 の記録尤度は「足す」モデルのまま、同じ情報源の繰り返しだけを置き換える。設計書への追記は X-15 と同じく人の確認を待つ（本 ADR が正）。
