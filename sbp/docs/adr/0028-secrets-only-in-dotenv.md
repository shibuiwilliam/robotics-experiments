# ADR-0028: シークレットは `.env` のみ。開発機の `.envrc` の実鍵は 3 本ともローテーションする（H-01）

- 日付: 2026-11-08
- 状態: 採択（ローテーションの実行はプロバイダ側の操作で、人が行う。完了の確認待ち）
- 触る層: なし（運用・文書）

## 文脈

開発機の `.envrc`（direnv）に LLM プロバイダ 3 社の API キーが平文で入っていた。git には一度も入っていない（`.gitignore` 済み）が、
2026-10-04 のセッションでファイルを表示したため、値がセッションの文脈を通過した。不変条件 12 は「シークレットは `.env` のみ」。

## 決定

1. **3 本すべてをローテーションする**（旧鍵を無効化し、新鍵を発行する）。「通過しただけ」でも漏洩とみなす。使用実績の追跡コストより発行し直す手間が小さい。
2. **鍵の置き場所は `.env` のみ。** `.envrc` には鍵も設定も置かない。X-11 で入れ子の設定も `.env` を読むようになったので、移して支障がない。
3. `.claude/settings.json` の deny に `.env`・`.env.local`・`.envrc`・`.envrc.*` の読み取りがあり、セッションから読めない。ローテーションの手順で新しい鍵を会話に貼らない。
4. 手順は ローテーション手順書（非公開。ローカルのみ）。実行したら `docs/HITL.md` H-01 を消す（人が行う）。

## 結果

- `make scan-secrets`（不変条件 12）が追跡ファイルの鍵を走査する。`.env.example` は鍵の項目を空で持つ。
- 限界: 旧鍵が無効化されたことの確認はプロバイダ側でしかできない。基盤側は確認できない。
